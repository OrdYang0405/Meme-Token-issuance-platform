## 二、知识回顾（5 分钟）

**Q1：MemeToken 的 SwapAndLiquify 将 LP Token 发送到了哪个地址？为什么？**

> 答案：回顾 `contracts/MemeToken.sol:249-256`，`addLiquidityETH` 的 `to` 参数设为 `address(this)`——合约自身。这意味着 LP Token 永久锁定在 MemeToken 合约中，没有人能提取。这是 Meme 代币的常见设计：自动增厚底池、永久不撤，给持有者信心。

**Q2：MemeToken 的 `_inSwap` 防重入锁在什么范围内生效？它保护了什么？**

> 答案：`contracts/MemeToken.sol:72` 声明、`:214` 加锁、`:224` 解锁。保护范围是 `_trySwapAndLiquify` 的整个执行过程（`:203-228`）。在 swap 中途如果 Uniswap 回调到 `_update`（卖出代币换 ETH 时），`_inSwap = true` 会让 `shouldTakeFee` 为 false，阻止税费扣取嵌套触发。

**Q3：MemeFactory 创建代币后，所有权是如何流转的？用户需要做什么才能完成接收？**

> 答案：`contracts/MemeFactory.sol:87` 调用 `newToken.transferOwnership(msg.sender)`，但 MemeToken 继承的是 `Ownable2Step`（`contracts/MemeToken.sol:31`），所以这只是将 `pendingOwner` 设为创建者。用户必须主动调用 `acceptOwnership()` 才能完成所有权接收。

**引入**：前面的课程中，我们主要关注功能的实现——创建代币、添加流动性、交易机制。但从安全角度看，一个 Meme 代币对投资者最大的风险是什么？答案是 **Rug Pull**——项目方突然撤走流动性，让所有持有者的代币变得一文不值。本课将系统性地解决这个问题。

## 三、流动性锁仓的核心概念（25 分钟）

### 3.1 什么是 Rug Pull？

Rug Pull 的经典操作流程：

```
1. 项目方创建代币
2. 添加初始流动性（代币 + ETH）
     → 获得 LP Token（流动性凭证）
3. 社区 FOMO 买入，推高代币价格
4. 项目方调用 removeLiquidity
     → 销毁 LP Token
     → 取走池中所有 ETH + 代币
5. 代币价格归零，社区血本无归
```

```
        正常项目                     Rug Pull
    ┌──────────────┐          ┌──────────────┐
    │ 流动性池      │          │ 流动性池      │
    │ ┌──────────┐ │          │ ┌──────────┐ │
    │ │ ETH  100  │ │          │ │ ETH  100  │ │ ←── 项目方撤走
    │ │ TOKEN 1M  │ │          │ │ TOKEN 1M  │ │ ←── 项目方撤走
    │ └──────────┘ │          │ └──────────┘ │
    │  LP Token 🔒  │          │  LP Token 🔓  │ ←── 关键区别
    └──────────────┘          └──────────────┘
```

> **课堂提问**：为什么说 LP Token 是 Rug Pull 的关键？
>
> **答案**：在 Uniswap V2 中，`removeLiquidity` 函数需要调用者持有 LP Token 作为凭证——谁持有 LP Token，谁就能提取池中的两种资产。如果项目方持有的 LP Token 没有被锁定，他随时可以撤走流动性。**锁仓的本质就是让 LP Token 在一段时间内（或永久）不可被转移/使用**。

### 3.2 锁仓的三种模式

| 模式 | 机制 | 适用场景 | 风险 |
|------|------|---------|------|
| **永久锁** | LP Token 转入黑洞地址 / 合约无提取函数 | 极致去中心化，如 SHIB 创世 | 流动性永远不会被提取，无法应对合约升级需求 |
| **时间锁** | LP Token 锁定到指定时间戳，到期后受益人可提取 | 大多数 Meme 代币（6-12 个月） | 到期后项目方仍可撤走流动性 |
| **分批解锁** | LP Token 分多批在不同时间解锁 | 机构级项目，线性释放 | 增加合约复杂度 |

**本课聚焦时间锁**，因为它是 Meme 代币最常见的选择——既提供了足够的安全保障，又保留了必要的灵活性。

```
时间锁模型：

锁仓时刻 (T0)                    解锁时刻 (T0 + lockDays)
    │                                    │
    ├────── 锁定期（不可提取）──────────┤
    │                                    │
    │  LP Token 托管在 Locker 合约中      │  LP Token 可被受益人提取
    │  任何人无法转移                     │  可以 removeLiquidity
    │                                    │
    └── 社区可以放心持有 ────────────────┘
```

### 3.3 时间锁的安全参数设计

**关键参数**：

1. **锁定时长（lockDays）**：通常 180 天 ~ 365 天（6 个月 ~ 1 年）
   - 太短（< 30 天）→ 社区不信任
   - 太长（> 5 年）→ 不现实，项目方可能不配合
   - Meme 代币常用：**180 天** 或 **365 天**

2. **受益人（beneficiary）**：解锁后谁能提取 LP Token
   - 通常设为代币的 owner（创建者）
   - 也可以设为 community multisig（多签钱包）
   - 极端情况：设为 `address(0)` → **等效永久锁**

3. **是否可以延长锁仓**：
   - `extendLock(lockId, additionalDays)` → 增强社区信任
   - 只能是延长（不能缩短），单向操作

4. **锁仓信息公开**：
   - 合约中提供 `getLockInfo(lockId)` 查询函数
   - 前端展示："XX 流动性已锁定至 2027-05-14"
   - 第三方平台（如 DEXTools）可直接读取合约状态

### 3.4 锁仓与 LP Token 的技术关系

LP Token 是 ERC20 代币（UniswapV2Pair 本身就是 ERC20）：

```solidity
// UniswapV2Pair 继承 ERC20 → LP Token 就是标准 ERC20
contract UniswapV2Pair is ERC20 {
    // ...
    function mint(address to) external lock returns (uint liquidity);
    function burn(address to) external lock returns (uint amount0, uint amount1);
}

// 锁仓 = 将 LP Token transfer 到 Locker 合约
lpToken.transfer(lockerAddress, lpAmount);

// 解锁 = Locker 合约将 LP Token transfer 回受益人
lpToken.transfer(beneficiary, lpAmount);

// removeLiquidity = 调用 Router，Router 内部调用 Pair.burn()
router.removeLiquidityETH(token, liquidity, amountTokenMin, amountETHMin, to, deadline);
```

> **课堂提问**：为什么不能直接在 MemeToken 合约中做锁仓，而需要一个独立的 LiquidityLocker 合约？
>
> **答案**：（1）**职责分离**：MemeToken 是 ERC20 代币，它的职责是代币的转账、税费、交易开关。LP 锁仓是完全不同的业务逻辑，混在一起会增加 MemeToken 的复杂度。（2）**通用性**：LiquidityLocker 可以锁定任意 ERC20 代币（不只是某一种 LP Token），可以被 MemeFactory 重复用于不同代币。（3）**审计焦点**：独立的 Locker 合约更容易被审计——审计者只需关注这个合约的逻辑是否正确，不需要审查整个 MemeToken。

## 四、LiquidityLocker 合约设计（20 分钟）

### 4.1 合约架构总览

```
MemeFactory
    │
    │  创建代币 + 锁定流动性
    │
    ├──→ MemeToken (新创建的代币)
    │
    ├──→ UniswapV2Router02.addLiquidityETH(...)
    │        │
    │        └──→ Pair (返回 LP Token)
    │
    └──→ LiquidityLocker
             │
             ├── lock(token, amount, lockDays, beneficiary)  → 记录锁仓
             ├── unlock(lockId)                                → 到期提取
             ├── extendLock(lockId, additionalDays)            → 延长锁仓
             └── getLockInfo(lockId)                           → 查询锁仓状态
```

### 4.2 状态变量与数据结构

```solidity
// 新建文件：contracts/LiquidityLocker.sol

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/access/Ownable2Step.sol";
import "@openzeppelin/contracts/token/ERC20/IERC20.sol";

contract LiquidityLocker is Ownable2Step {

    // ============ 锁仓记录结构体 ============
    struct LockRecord {
        address token;           // LP Token 地址
        uint256 amount;          // 锁仓数量（以 LP Token 的最小单位计）
        uint256 unlockTime;      // 解锁时间戳（Unix timestamp，精确到秒）
        address beneficiary;     // 解锁后 LP Token 的接收者
        bool withdrawn;          // 是否已提取
    }

    // ============ 存储 ============
    LockRecord[] public locks;   // 所有锁仓记录（数组，按 lockId 索引）

    // ============ 事件 ============
    event LiquidityLocked(
        uint256 indexed lockId,       // 锁仓记录 ID
        address indexed token,        // LP Token 地址
        address indexed beneficiary,  // 受益人
        uint256 amount,               // 锁仓数量
        uint256 unlockTime            // 解锁时间
    );

    event LiquidityUnlocked(
        uint256 indexed lockId,
        address indexed token,
        address indexed beneficiary,
        uint256 amount
    );

    event LockExtended(
        uint256 indexed lockId,
        uint256 oldUnlockTime,
        uint256 newUnlockTime
    );

    // ============ 构造函数 ============
    constructor() Ownable(msg.sender) {}
}
```

### 4.3 核心函数：lock —— 锁定 LP Token

```solidity
    // ============ 核心：锁定流动性 ============

    /**
     * @notice 锁定 LP Token 到合约中
     * @param _token LP Token 地址（UniswapV2Pair 地址）
     * @param _amount 锁仓数量
     * @param _lockDays 锁仓天数（如 180 = 约 6 个月）
     * @param _beneficiary 解锁后的受益人（如代币创建者地址）
     * @return lockId 锁仓记录 ID
     */
    function lock(
        address _token,
        uint256 _amount,
        uint256 _lockDays,
        address _beneficiary
    ) external returns (uint256 lockId) {
        require(_token != address(0), "zero token");
        require(_amount > 0, "zero amount");
        require(_lockDays > 0, "zero lock days");
        require(_lockDays <= 3650, "lock too long"); // 最长 10 年
        require(_beneficiary != address(0), "zero beneficiary");

        uint256 unlockTime = block.timestamp + (_lockDays * 1 days);

        lockId = locks.length;

        locks.push(LockRecord({
            token: _token,
            amount: _amount,
            unlockTime: unlockTime,
            beneficiary: _beneficiary,
            withdrawn: false
        }));

        // 将 LP Token 从调用者转入本合约
        IERC20(_token).transferFrom(msg.sender, address(this), _amount);

        emit LiquidityLocked(lockId, _token, _beneficiary, _amount, unlockTime);
    }
```

**关键设计决策分析**：

1. **谁调用 lock？** → MemeFactory 在给代币添加初始流动性后调用，`msg.sender` 为 Factory。或者代币创建者自己先获得 LP Token，再调用 Locker 锁仓。

2. **LP Token 如何到 Locker 中？** → 使用 `transferFrom`，调用者需要先 `approve` Locker 合约。这一步在 Factory 的创建流程中自动完成。

3. **最大锁仓 10 年** → 防止误操作（`lockDays = 100000` 会导致时间戳溢出或实际上永远不会解锁）。3650 天 = 10 年已经足够长。

### 4.4 核心函数：unlock —— 到期解锁

```solidity
    /**
     * @notice 到期后提取锁定的 LP Token
     * @param _lockId 锁仓记录 ID
     */
    function unlock(uint256 _lockId) external {
        require(_lockId < locks.length, "invalid lock id");

        LockRecord storage record = locks[_lockId];
        require(!record.withdrawn, "already withdrawn");
        require(block.timestamp >= record.unlockTime, "still locked");
        require(
            msg.sender == record.beneficiary || msg.sender == owner(),
            "not authorized"
        );

        record.withdrawn = true;

        // 将 LP Token 转给受益人
        IERC20(record.token).transfer(record.beneficiary, record.amount);

        emit LiquidityUnlocked(_lockId, record.token, record.beneficiary, record.amount);
    }
```

**授权设计**：解锁权限开放给两类人：
- `beneficiary`（受益人本人）——最常用的路径
- `owner()`（合约管理员）——紧急备用路径

> **课堂提问**：如果把 `unlock` 的权限只限于 `beneficiary`（去掉 `owner()` 判断），会有什么风险？
>
> **答案**：如果 `beneficiary` 的私钥丢失，LP Token 将永远无法提取（因为没有其他人可以代为提取）。给 `owner()` 保留权限是一种安全兜底。但这也意味着 Locker 的 owner 可以提取任意锁仓的 LP Token——所以 Locker 合约的 owner 应该设为一个可信地址（如多签钱包或 TimelockController）。

### 4.5 延长锁仓函数

```solidity
    /**
     * @notice 延长锁仓时间（只能延长，不能缩短）
     * @param _lockId 锁仓记录 ID
     * @param _additionalDays 额外增加的天数
     */
    function extendLock(uint256 _lockId, uint256 _additionalDays) external {
        require(_lockId < locks.length, "invalid lock id");

        LockRecord storage record = locks[_lockId];
        require(!record.withdrawn, "already withdrawn");
        require(
            msg.sender == record.beneficiary || msg.sender == owner(),
            "not authorized"
        );
        require(_additionalDays > 0, "zero additional days");

        uint256 oldUnlockTime = record.unlockTime;
        uint256 newUnlockTime = oldUnlockTime + (_additionalDays * 1 days);
        require(newUnlockTime > oldUnlockTime, "overflow"); // 防溢出

        record.unlockTime = newUnlockTime;

        emit LockExtended(_lockId, oldUnlockTime, newUnlockTime);
    }
```

**为什么 extendLock 很重要？**

这是一个**社群信任信号**。当项目方主动延长锁仓期，向社区传递的信息是："我们不急着撤流动性，我们对项目长期有信心。"在 DEXTools、DexScreener 等平台上，延长锁仓是一个正面信号。

### 4.6 查询函数

```solidity
    // ============ 查询函数 ============

    function totalLocks() external view returns (uint256) {
        return locks.length;
    }

    /**
     * @notice 获取单个锁仓记录的完整信息
     */
    function getLockInfo(uint256 _lockId)
        external
        view
        returns (LockRecord memory)
    {
        require(_lockId < locks.length, "invalid lock id");
        return locks[_lockId];
    }

    /**
     * @notice 获取锁仓记录的剩余锁定时间（秒）
     * @return 剩余秒数，0 表示已可解锁
     */
    function getRemainingLockTime(uint256 _lockId)
        external
        view
        returns (uint256)
    {
        if (_lockId >= locks.length) return 0;

        LockRecord storage record = locks[_lockId];
        if (record.withdrawn) return 0;
        if (block.timestamp >= record.unlockTime) return 0;

        return record.unlockTime - block.timestamp;
    }

    /**
     * @notice 获取某个代币（LP Token）的所有锁仓记录 ID
     */
    function getLocksByToken(address _token)
        external
        view
        returns (uint256[] memory)
    {
        // 先统计数量
        uint256 count = 0;
        for (uint256 i = 0; i < locks.length; i++) {
            if (locks[i].token == _token) {
                count++;
            }
        }

        // 填充结果
        uint256[] memory result = new uint256[](count);
        uint256 index = 0;
        for (uint256 i = 0; i < locks.length; i++) {
            if (locks[i].token == _token) {
                result[index] = i;
                index++;
            }
        }

        return result;
    }

    /**
     * @notice 获取某个受益人的所有锁仓记录 ID
     */
    function getLocksByBeneficiary(address _beneficiary)
        external
        view
        returns (uint256[] memory)
    {
        uint256 count = 0;
        for (uint256 i = 0; i < locks.length; i++) {
            if (locks[i].beneficiary == _beneficiary) {
                count++;
            }
        }

        uint256[] memory result = new uint256[](count);
        uint256 index = 0;
        for (uint256 i = 0; i < locks.length; i++) {
            if (locks[i].beneficiary == _beneficiary) {
                result[index] = i;
                index++;
            }
        }

        return result;
    }

    /**
     * @notice 快速判断某代币是否仍有有效锁仓（用于前端显示锁仓徽章）
     */
    function isTokenLocked(address _token) external view returns (bool) {
        for (uint256 i = 0; i < locks.length; i++) {
            if (locks[i].token == _token && !locks[i].withdrawn) {
                return true;
            }
        }
        return false;
    }
```

**查询函数的设计考量**：

| 函数 | 用途 | 调用者 |
|------|------|--------|
| `totalLocks()` | 了解合约中总锁仓数 | 统计面板 |
| `getLockInfo(lockId)` | 获取具体锁仓详情（结构体全部字段） | 前端详情页 |
| `getRemainingLockTime(lockId)` | 获取剩余锁仓时间（秒） | 前端倒计时 |
| `getLocksByToken(token)` | 按 LP Token 查锁仓（支持一个池多次锁仓） | 代币详情页 |
| `getLocksByBeneficiary(addr)` | 按受益人查锁仓 | "我的锁仓"页面 |
| `isTokenLocked(token)` | 快速判断是否已被锁（返回 bool） | 列表页锁仓徽章 |

## 五、MemeFactory 集成 LiquidityLocker（20 分钟）

### 5.1 集成目标

当前 MemeFactory 的 `createToken` 流程：

```
createToken → 部署 MemeToken → 转移所有权 → 记录 → 完成
```

集成后的目标流程：

```
createToken → 部署 MemeToken → 转移所有权 → 添加初始流动性
    → 将 LP Token 锁定到 LiquidityLocker → 记录 → 完成
```

### 5.2 修改后的 MemeFactory（集成锁仓）

```solidity
// 在 contracts/MemeFactory.sol 基础上新增以下内容：

// ============ 新增：流动性锁仓集成 ============

// 新增状态变量
LiquidityLocker public liquidityLocker;                // Locker 合约引用
IUniswapV2Router02 public uniswapRouter;              // Router 合约引用
uint256 public defaultLockDays = 180;                  // 默认锁仓天数

// 新增事件
event LiquidityLockedForToken(
    address indexed token,
    uint256 lockId,
    uint256 lockDays,
    uint256 unlockTime
);

/**
 * @notice 设置 LiquidityLocker 合约地址
 */
function setLiquidityLocker(address _locker) external onlyOwner {
    require(_locker != address(0), "zero locker");
    liquidityLocker = LiquidityLocker(_locker);
}

/**
 * @notice 设置 Uniswap Router 地址（用于添加初始流动性）
 */
function setUniswapRouter(address _router) external onlyOwner {
    require(_router != address(0), "zero router");
    uniswapRouter = IUniswapV2Router02(_router);
}

/**
 * @notice 设置默认锁仓天数
 */
function setDefaultLockDays(uint256 _days) external onlyOwner {
    require(_days >= 30 && _days <= 3650, "invalid lock days");
    defaultLockDays = _days;
}

/**
 * @notice 创建代币 + 添加初始流动性 + 锁仓（一体化函数）
 * @param _params 代币参数（与之前相同）
 * @param _initialLiquidityETH 初始流动性 ETH 数量
 * @dev 调用者需同时发送 creationFee + _initialLiquidityETH
 */
function createTokenWithLiquidity(
    TokenParams calldata _params,
    uint256 _initialLiquidityETH
) external payable returns (address tokenAddr, uint256 lockId) {
    require(address(liquidityLocker) != address(0), "locker not set");
    require(address(uniswapRouter) != address(0), "router not set");
    require(_initialLiquidityETH > 0, "zero liquidity");

    // ─── 步骤 1：创建代币 ───
    // 复用已有逻辑
    uint256 fee = creationFee;
    require(msg.value >= fee + _initialLiquidityETH, "insufficient value");

    tokenAddr = _createToken(_params);  // 内部函数，提取原 createToken 逻辑

    // ─── 步骤 2：创建 Uniswap Pair 并设置 ───
    MemeToken token = MemeToken(tokenAddr);
    token.setUniswapRouter(address(uniswapRouter));

    address weth = uniswapRouter.WETH();
    address factoryAddr = uniswapRouter.factory();

    IUniswapV2Factory factory = IUniswapV2Factory(factoryAddr);
    factory.createPair(tokenAddr, weth);
    address pair = factory.getPair(tokenAddr, weth);
    token.setUniswapPair(pair);

    // ─── 步骤 3：计算代币端流动性 ───
    // 将 totalSupply 的一定比例用于初始流动性（如 80%）
    uint256 decimals = 10 ** token.decimals();
    uint256 totalSupplyWei = _params.totalSupply * decimals;
    uint256 liquidityTokens = (totalSupplyWei * 80) / 100;

    // ─── 步骤 4：添加流动性 ───
    token.approve(address(uniswapRouter), liquidityTokens);

    uniswapRouter.addLiquidityETH{value: _initialLiquidityETH}(
        tokenAddr,
        liquidityTokens,
        0,                    // amountTokenMin
        0,                    // amountETHMin
        address(this),        // LP Token 先到 Factory
        block.timestamp + 600
    );

    // ─── 步骤 5：获取 LP Token ───
    uint256 lpBalance = IERC20(pair).balanceOf(address(this));

    // ─── 步骤 6：锁定 LP Token ───
    IERC20(pair).approve(address(liquidityLocker), lpBalance);
    lockId = liquidityLocker.lock(
        pair,
        lpBalance,
        defaultLockDays,
        msg.sender              // 受益人为代币创建者
    );

    // ─── 步骤 7：启用交易 ───
    token.enableTrading();

    emit LiquidityLockedForToken(tokenAddr, lockId, defaultLockDays,
        block.timestamp + defaultLockDays * 1 days);
}
```

```typescript
// 文件：frontend/src/locker.ts

import { Contract, BrowserProvider } from "ethers";

// ─── LiquidityLocker 的完整 ABI ───
const LOCKER_ABI = [
    "function getLockInfo(uint256) view returns (tuple(address token, uint256 amount, uint256 unlockTime, address beneficiary, bool withdrawn))",
    "function getLocksByToken(address) view returns (uint256[])",
    "function getRemainingLockTime(uint256) view returns (uint256)",
    "function isTokenLocked(address) view returns (bool)",
    "function totalLocks() view returns (uint256)",
];

// Locker 合约地址（部署后替换）
const LOCKER_ADDRESS = "0x...";

export interface LockInfo {
    lockId: number;
    token: string;
    amount: bigint;
    unlockTime: number;
    beneficiary: string;
    withdrawn: boolean;
    remainingSeconds: number;
    isExpired: boolean;
}

/**
 * 获取某个代币的锁仓状态
 */
export async function getTokenLockStatus(
    provider: BrowserProvider,
    tokenPairAddress: string
): Promise<LockInfo[]> {
    const locker = new Contract(LOCKER_ADDRESS, LOCKER_ABI, provider);

    // 快速检查
    const isLocked: boolean = await locker.isTokenLocked(tokenPairAddress);
    if (!isLocked) return [];

    // 获取所有锁仓 ID
    const lockIds: bigint[] = await locker.getLocksByToken(tokenPairAddress);

    // 并行获取每个锁仓的详细信息
    const results: LockInfo[] = [];
    for (const lockId of lockIds) {
        const [info, remaining] = await Promise.all([
            locker.getLockInfo(lockId),
            locker.getRemainingLockTime(lockId),
        ]);

        results.push({
            lockId: Number(lockId),
            token: info.token,
            amount: info.amount,
            unlockTime: Number(info.unlockTime),
            beneficiary: info.beneficiary,
            withdrawn: info.withdrawn,
            remainingSeconds: Number(remaining),
            isExpired: Number(info.unlockTime) * 1000 < Date.now(),
        });
    }

    return results;
}

/**
 * 格式化剩余时间
 */
export function formatRemainingTime(seconds: number): string {
    if (seconds <= 0) return "已到期";

    const days = Math.floor(seconds / 86400);
    const hours = Math.floor((seconds % 86400) / 3600);
    const minutes = Math.floor((seconds % 3600) / 60);

    const parts: string[] = [];
    if (days > 0) parts.push(`${days} 天`);
    if (hours > 0) parts.push(`${hours} 小时`);
    if (minutes > 0) parts.push(`${minutes} 分`);

    return parts.join(" ") || "即将到期";
}
```

```typescript
function renderLockBadge(lockStatus: LockInfo[]): string {
    if (lockStatus.length === 0) {
        // 未锁仓 → 警告
        return `<span class="badge badge-danger" title="流动性未锁定，存在 Rug Pull 风险">
            ⚠️ 未锁仓
        </span>`;
    }

    // 检查是否有有效的锁仓（未提取 + 未到期或已提取）
    const activeLocks = lockStatus.filter(l => !l.withdrawn);

    if (activeLocks.length === 0) {
        // 全部已提取 → 高风险
        return `<span class="badge badge-danger" title="所有锁仓已提取">
            ⚠️ 已解锁
        </span>`;
    }

    // 有有效锁仓 → 显示最短剩余时间
    const minRemaining = Math.min(...activeLocks.map(l => l.remainingSeconds));

    if (minRemaining <= 0) {
        // 所有锁仓已到期但未提取 → 中等风险
        return `<span class="badge badge-warning" title="锁仓已到期，可随时提取">
            🔓 已到期
        </span>`;
    }

    // 有有效锁仓 → 安全
    const remaining = formatRemainingTime(minRemaining);
    return `<span class="badge badge-success" title="流动性已锁定">
        🔒 ${remaining}
    </span>`;
}
```

```typescript
export interface SecurityReport {
    score: number;          // 0-100 的安全评分
    checks: SecurityCheck[];
    summary: string;
}

export interface SecurityCheck {
    name: string;
    passed: boolean;
    riskLevel: "low" | "medium" | "high" | "critical";
    detail: string;
}

/**
 * 对某个代币执行全面的安全检查
 */
export async function runSecurityCheck(
    provider: BrowserProvider,
    tokenAddress: string,
    pairAddress: string
): Promise<SecurityReport> {
    const checks: SecurityCheck[] = [];
    const token = new Contract(tokenAddress, MEME_TOKEN_ABI, provider);

    // ─── 检查 1：LP 锁仓 ───
    const lockStatus = await getTokenLockStatus(provider, pairAddress);
    const hasActiveLock = lockStatus.some(l => !l.withdrawn && !l.isExpired);
    checks.push({
        name: "LP 流动性锁仓",
        passed: hasActiveLock,
        riskLevel: hasActiveLock ? "low" : "critical",
        detail: hasActiveLock
            ? `流动性已锁定至 ${new Date(lockStatus[0].unlockTime * 1000).toLocaleDateString()}`
            : "流动性未被锁定，项目方可随时撤走流动性",
    });

    // ─── 检查 2：税率上限 ───
    const maxTax = await token.MAX_TAX();
    checks.push({
        name: "税率上限",
        passed: Number(maxTax) <= 2500,
        riskLevel: Number(maxTax) <= 2500 ? "low" : "high",
        detail: `最高税率: ${Number(maxTax) / 100}%`,
    });

    // ─── 检查 3：Owner 持币比例 ───
    const totalSupply = await token.totalSupply();
    const ownerBalance = await token.balanceOf(await token.owner());
    const ownerPercent = (Number(ownerBalance) / Number(totalSupply)) * 100;
    checks.push({
        name: "Owner 持币比例",
        passed: ownerPercent < 5,
        riskLevel: ownerPercent < 5 ? "low" : ownerPercent < 20 ? "medium" : "high",
        detail: `Owner 持有 ${ownerPercent.toFixed(2)}% 的代币`,
    });

    // ─── 检查 4：Owner 是否排除税费 ───
    const ownerExcluded = await token.isExcludedFromFee(await token.owner());
    checks.push({
        name: "Owner 免税状态",
        passed: !ownerExcluded,
        riskLevel: ownerExcluded ? "medium" : "low",
        detail: ownerExcluded
            ? "Owner 被排除在税费之外，可免税买卖"
            : "Owner 正常缴纳税费",
    });

    // ─── 检查 5：交易是否已启用 ───
    const tradingEnabled = await token.tradingEnabled();
    checks.push({
        name: "交易状态",
        passed: tradingEnabled,
        riskLevel: tradingEnabled ? "low" : "medium",
        detail: tradingEnabled ? "交易已启用" : "交易未启用",
    });

    // 计算安全评分
    const passedCount = checks.filter(c => c.passed).length;
    const score = Math.round((passedCount / checks.length) * 100);

    return {
        score,
        checks,
        summary: score >= 80 ? "安全性良好" : score >= 50 ? "存在中等风险" : "存在高风险，请谨慎",
    };
```

## 八、合约所有权审计与开源验证（10 分钟）

### 8.1 Ownable2Step 的所有权状态机

MemeToken 使用 `Ownable2Step`（而非 `Ownable`）：

```
状态1: owner = A, pendingOwner = address(0)
    │
    ├── A 调用 transferOwnership(B)
    │   └── pendingOwner = B
    │       │
    │       ├── B 调用 acceptOwnership()
    │       │   └── owner = B, pendingOwner = address(0)  ✓ 完成
    │       │
    │       └── B 不调用（遗忘了）
    │           └── owner 仍为 A（但 A 已无法操作）
    │
    └── A 调用 renounceOwnership()
        └── owner = address(0), pendingOwner = address(0)  ✗ 永久放弃
```

**审计检查点**：

```typescript
// 文件：frontend/src/ownership.ts

export interface OwnershipStatus {
    owner: string;
    pendingOwner: string;
    isRenounced: boolean;
    isTransferPending: boolean;
    statusText: string;
}

export async function checkOwnership(
    provider: BrowserProvider,
    tokenAddress: string
): Promise<OwnershipStatus> {
    const token = new Contract(tokenAddress, MEME_TOKEN_ABI, provider);

    const owner = await token.owner();
    const pendingOwner = await token.pendingOwner();

    const isRenounced = owner === ethers.ZeroAddress;
    const isTransferPending = pendingOwner !== ethers.ZeroAddress;

    let statusText: string;
    if (isRenounced) {
        statusText = "所有权已放弃（无法修改合约参数）";
    } else if (isTransferPending) {
        statusText = "所有权转移中（pendingOwner 需调用 acceptOwnership）";
    } else {
        statusText = "所有权正常";
    }

    return { owner, pendingOwner, isRenounced, isTransferPending, statusText };
}
```

### 8.2 所有权的四种典型状态

| 状态 | owner | pendingOwner | 含义 | 安全性 |
|------|-------|-------------|------|--------|
| 正常持有 | 创建者地址 | `0x0` | 创建者完全控制合约 | 取决于其他安全措施 |
| 转移中 | 创建者地址 | 新地址 | 两步转移的第一步已完成 | 等待新 owner 接收 |
| 已放弃 | `0x0` | `0x0` | `renounceOwnership()` 已被调用 | **最高**（参数不可改，但也无法修复漏洞） |
| 锁定中 | 多签/DAO | `0x0` | 由多签钱包或治理合约控制 | 中高（取决于多签阈值） |

> **课堂提问**：为什么"已放弃所有权"不一定是好事？
>
> **答案**：放弃所有权意味着合约参数永远不可更改。如果发现严重漏洞（如税费计算错误导致代币无法交易），无法修复。如果 SwapAndLiquify 需要调整参数，也无法调整。**安全不是最大化不可变性，而是最大化可预测性和透明度。**一个好的项目应该保留必要的管理权限，同时通过锁仓、多签、时间锁等机制限制这些权限的滥用。
