## 二、知识回顾（5 分钟）

请学生回答以下问题：

**Q1：MemeFactory 合约提供了哪些查询接口？**

> 答案：
> - `totalTokens()` → `uint256`：返回已创建代币总数（`contracts/MemeFactory.sol:112`）
> - `getTokensPaginated(offset, limit)` → `(address[] tokens, uint256 total)`：分页查询代币地址列表（`contracts/MemeFactory.sol:124`）
> - `getTokensByCreator(creator)` → `address[]`：查询某个地址创建的所有代币（`contracts/MemeFactory.sol:116`）
> - `getTokenCountByCreator(creator)` → `uint256`：查询某个地址创建的代币数量（`contracts/MemeFactory.sol:120`）
> - `tokenParams(tokenAddress)` → `TokenParams`：查询某个代币的创建参数（`contracts/MemeFactory.sol:26` 声明映射）
> - `creationFee()` → `uint256`：当前创建费用（`contracts/MemeFactory.sol:20`）

**Q2：createToken 的参数结构体 TokenParams 包含哪些字段？各自有什么限制？**

> 答案：定义在 `contracts/MemeFactory.sol:8-17`
> ```solidity
> struct TokenParams {
>     string name;           // 代币名称，1-32 字符
>     string symbol;         // 代币符号，1-8 字符
>     uint256 totalSupply;   // 总供应量，1,000 ~ 1,000,000,000,000
>     address marketingWallet;  // 营销钱包，非零地址
>     address teamWallet;       // 团队钱包，非零地址
>     uint256 buyTax;           // 买入税（基点制），≤ 2500
>     uint256 sellTax;          // 卖出税（基点制），≤ 2500
> }
> ```
> 这些限制在 `contracts/MemeFactory.sol:61-73` 的 `_validateParams` 逻辑中校验。常量定义在 `contracts/MemeFactory.sol:29-32`。

**Q3：调用 createToken 时需要附带什么？为什么？**

> 答案：需要附带 `msg.value >= creationFee`（`contracts/MemeFactory.sol:57`）。目的是防止 spam 创建（任何人零成本无限发币会污染链上数据），同时也构成平台的收入来源。创建费用上限为 `MAX_CREATION_FEE = 10 ether`（`contracts/MemeFactory.sol:21`）。

**Q4：代币创建后，所有权是如何转移给用户的？**

> 答案：代币创建时 owner 初始为工厂合约自身，然后工厂调用 `newToken.transferOwnership(msg.sender)`（`contracts/MemeFactory.sol:87`）。由于 MemeToken 继承的是 `Ownable2Step`（`contracts/MemeToken.sol:31`），这只是将 `pendingOwner` 设为创建者，用户还需要主动调用 `acceptOwnership()` 完成所有权接收。这个两步设计防止了所有权被误转到无法操作的地址。

**引入**：现在我们有了功能完备的工厂合约，但用户需要通过 MetaMask 直接在网页上操作，而不是在命令行敲 Hardhat 脚本。本课将完成从"命令行开发者工具"到"用户可用的 DApp"的关键一步。

## 三、DApp 前端架构概述（15 分钟）

### 3.1 前端与合约的交互模型

```
浏览器 (前端)                        以太坊网络
    │                                    │
    ├── 1. 读取合约 (view / pure) ────────→ 免费，不需要 gas，不触发 MetaMask
    │        ← 返回数据 ────────────────┤     通过 provider.call() 执行
    │                                    │
    ├── 2. 发起交易 (写操作) ──────────────→ 需要 gas + 用户签名
    │        ← 交易收据 (receipt) ───────┤     通过 signer.sendTransaction() 执行
    │                                    │
    └── 3. 监听事件 (Event) ──────────────→ 实时更新 UI
                                            通过 provider.on() / contract.on() 订阅
```

**核心工具**：ethers.js v6（已随 `@nomicfoundation/hardhat-toolbox` 安装，见 `package.json:13`）。

### 3.2 技术选型对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| 纯 HTML + ethers.js CDN | 零配置，立即上手 | 不支持 TypeScript，无热更新 | 极简 demo |
| Vite + TypeScript 原生 | 类型安全，HMR 热更新，构建产物小 | 需要配置 vite.config.ts | **本课选择** |
| Next.js / React | 生态丰富，SSR | 学习曲线陡，重心偏离合约 | 生产级 DApp |

**本课选择 Vite + TypeScript 原生的理由**：
- 与 Hardhat 项目的 TypeScript 配置一致（复用 `tsconfig.json:1-7` 的类型系统）
- 可以直接导入 TypeChain 生成的类型定义（`typechain-types/` 目录），享受完整的类型提示
- 不引入框架概念，学生能专注于"ethers.js 如何与合约交互"这一核心问题

### 3.3 前端目录结构（在 `frontend/` 下新建）

```
frontend/
├── index.html                  ← 入口 HTML，包含表单和列表容器
├── package.json                ← 前端独立的 npm 依赖（vite, ethers）
├── tsconfig.json               ← 前端 TS 配置（与根目录的区分）
├── vite.config.ts              ← Vite 构建配置（路径别名指向 ../typechain-types）
└── src/
    ├── main.ts                 ← 应用入口：初始化钱包、绑定事件、加载列表
    ├── config.ts               ← 合约地址常量 + TypeChain 类型导入
    ├── wallet.ts               ← 钱包连接 / 切换监听 / 网络检测模块
    ├── factory.ts              ← MemeFactory 合约交互（只读 + 写入）模块
    └── ui.ts                   ← DOM 操作：表单校验、列表渲染、状态反馈
```

**为什么前端需要独立的 `package.json`？**
前端只需要 `ethers` 和 `vite`，不需要 `hardhat`、`@openzeppelin/contracts` 等Solidity 工具链。分离依赖可以加快安装速度，也符合"前端构建产物与合约编译产物分离"的工程实践。

## 四、钱包连接模块 —— `frontend/src/wallet.ts`（25 分钟）

### 4.1 MetaMask 注入原理与检测

MetaMask 安装后，会在每个网页注入 `window.ethereum` 对象（遵循 EIP-1193 标准）。所有钱包交互都通过这个对象完成。

```typescript
// 文件：frontend/src/wallet.ts（第1-8行）

// 检测 MetaMask 是否安装
export function getEthereum(): any {
    const { ethereum } = window as any;
    if (!ethereum) {
        // 如果未安装，引导用户去安装
        throw new Error("请安装 MetaMask 插件 (https://metamask.io)");
    }
    return ethereum;
}
```

**EIP-1193 标准化的核心 API**（前端必需了解的 5 个方法）：

| 方法 / 事件 | 类型 | 用途 |
|------------|------|------|
| `eth_requestAccounts` | 请求方法 | 弹窗请求用户授权账户访问（首次连接） |
| `eth_chainId` | 请求方法 | 获取当前链 ID（十六进制字符串） |
| `eth_accounts` | 请求方法 | 获取已授权账户（不弹窗，静默获取） |
| `accountsChanged` | 监听事件 | 用户在 MetaMask 切换账户时触发 |
| `chainChanged` | 监听事件 | 用户在 MetaMask 切换网络时触发 |

> **课堂提问**：`eth_requestAccounts` 和 `eth_accounts` 的区别是什么？
>
> **答案**：`eth_requestAccounts` 会弹出 MetaMask 授权窗口，需要用户主动点击确认；`eth_accounts` 是静默调用，如果用户之前已授权则返回账户列表，未授权则返回空数组。页面初始化时应先用 `eth_accounts` 检查是否已授权，避免不必要的弹窗打扰用户。

### 4.2 连接钱包函数

```typescript
// 文件：frontend/src/wallet.ts（第10-28行）

import { BrowserProvider } from "ethers";

export interface WalletState {
    address: string;            // 当前账户地址
    provider: BrowserProvider;  // ethers.js v6 浏览器 Provider
    chainId: number;            // 当前链 ID（十进制）
}

export async function connectWallet(): Promise<WalletState> {
    const ethereum = getEthereum();

    // 步骤1：弹窗请求用户授权（用户必须手动确认）
    const accounts: string[] = await ethereum.request({
        method: "eth_requestAccounts",
    });

    if (accounts.length === 0) {
        throw new Error("未获取到账户，请检查 MetaMask 是否已解锁");
    }

    // 步骤2：创建 ethers.js v6 的 BrowserProvider
    // BrowserProvider 封装了 window.ethereum，自动处理签名请求
    const provider = new BrowserProvider(ethereum);

    // 步骤3：获取链 ID（返回值是十六进制如 "0xaa36a7"，需转十进制）
    const chainIdHex: string = await ethereum.request({ method: "eth_chainId" });
    const chainId = parseInt(chainIdHex, 16);

    return { address: accounts[0], provider, chainId };
}
```

**关键设计决策：Provider 与 Signer 的分离**

在 ethers.js v6 中：
- `BrowserProvider` — 只读访问区块链 + 管理账户连接。调用 `provider.call()` 执行 view 函数，不需要用户签名。
- `Signer` — 通过 `provider.getSigner()` 获取，用于签名交易。每次写操作都需要 MetaMask 弹窗确认。

```
BrowserProvider ──[getSigner()]──→ Signer
     │                                │
     ├── provider.call(tx)            ├── signer.sendTransaction(tx)
     ├── provider.getBalance(addr)    ├── contract.writeMethod(args)
     └── provider.on("block", ...)    └── 每次调用都弹出 MetaMask 确认窗口
```

> **课堂提问**：为什么要分离 Provider 和 Signer？都用 Signer 不行吗？
>
> **答案**：两个原因。（1）用户体验：用 Provider 读取数据不需要 MetaMask 弹窗，页面可以流畅加载。如果每次读数据都弹窗，用户会非常烦躁。（2）安全性：Provider 不需要用户私钥签名，可以在未连接钱包时仍展示"浏览"功能（如查看代币列表），提升 DApp 的可用性。这也是 Uniswap 等主流 DApp 的做法——"先浏览，需要交易时再连接钱包"。

### 4.3 监听账户与网络变化

```typescript
// 文件：frontend/src/wallet.ts（第30-48行）

export function watchWalletChanges(
    onAccountChange: (address: string | null) => void
): void {
    const ethereum = getEthereum();

    // 事件1：用户切换账户
    // 注意：回调参数是字符串数组，取第一个元素
    ethereum.on("accountsChanged", (accounts: string[]) => {
        if (accounts.length === 0) {
            // 用户断开了所有账户（在 MetaMask 中点击了"断开连接"）
            onAccountChange(null);
        } else {
            // 用户切换到了另一个账户
            onAccountChange(accounts[0]);
        }
    });

    // 事件2：用户切换网络
    // 不同网络的合约地址不同、链 ID 不同、状态完全不同
    // 最安全的做法是直接重新加载页面
    ethereum.on("chainChanged", () => {
        window.location.reload();
    });
}
```

> **课堂提问**：`chainChanged` 时为什么建议直接 `window.location.reload()` 而不是静默更新状态？
>
> **答案**：切换网络后，以下所有状态都可能不一致：（1）合约地址完全不同（Factory 在 Sepolia 和 Hardhat 上地址不同）；（2）用户的代币余额完全不同；（3）链上数据完全不同；（4）当前 Provider 连接的 RPC 已变化。逐一更新这些状态非常容易遗漏，而 `reload()` 是最安全、最彻底的方案。大多数主流 DApp（Uniswap、Aave）也采用这个做法。

### 4.4 网络检测与切换引导

```typescript
// 文件：frontend/src/wallet.ts（第50-78行）

// 支持的链 ID 映射
export const SUPPORTED_CHAINS: Record<number, { name: string; rpcUrl: string }> = {
    31337:   { name: "Hardhat Local",     rpcUrl: "http://127.0.0.1:8545" },
    11155111:{ name: "Sepolia Testnet",   rpcUrl: "https://eth-sepolia.g.alchemy.com/v2/YOUR_KEY" },
};

export function checkNetwork(chainId: number): void {
    if (!SUPPORTED_CHAINS[chainId]) {
        // 列出支持的链名称，方便用户理解
        const names = Object.values(SUPPORTED_CHAINS).map(c => c.name).join(" / ");
        throw new Error(`当前网络不支持。请切换到: ${names}`);
    }
}

// 进阶：主动引导用户切换网络（通过 wallet_switchEthereumChain）
export async function switchNetwork(targetChainId: number): Promise<void> {
    const ethereum = getEthereum();
    const chainIdHex = "0x" + targetChainId.toString(16);

    try {
        // 尝试直接切换（用户已添加过该网络）
        await ethereum.request({
            method: "wallet_switchEthereumChain",
            params: [{ chainId: chainIdHex }],
        });
    } catch (err: any) {
        // 错误码 4902：用户未添加过该网络，需要先添加
        if (err.code === 4902) {
            const chain = SUPPORTED_CHAINS[targetChainId];
            await ethereum.request({
                method: "wallet_addEthereumChain",
                params: [{
                    chainId: chainIdHex,
                    chainName: chain.name,
                    rpcUrls: [chain.rpcUrl],
                }],
            });
        } else {
            throw err;
        }
    }
}
```

**补充**：`wallet_switchEthereumChain` 和 `wallet_addEthereumChain` 也属于 EIP-3085 和 EIP-3326 标准，主流钱包（MetaMask、Rabby）都支持。

## 五、合约交互模块 —— `frontend/src/factory.ts`（30 分钟）

### 5.1 从 Hardhat 编译产物获取 ABI 和类型

每次运行 `npx hardhat compile`（`package.json:6`），Hardhat 会生成两样关键产物：

1. **ABI（Application Binary Interface）**：`artifacts/contracts/MemeFactory.sol/MemeFactory.json`
2. **TypeChain 类型**：`typechain-types/contracts/MemeFactory.sol/MemeFactory.ts`

前端需要用到的是 TypeChain 生成的类型，它提供了类型安全的合约绑定。

```typescript
// 文件：frontend/src/config.ts（第1-20行）

// 从 TypeChain 导入工厂合约的类型和工厂类
import type { MemeFactory } from "../../typechain-types/contracts/MemeFactory.sol/MemeFactory";
import { MemeFactory__factory } from "../../typechain-types/factories/contracts/MemeFactory.sol/MemeFactory__factory";

// ─── 合约地址（部署后替换为实际地址）───
// 开发时：部署到 localhost 后，从终端输出中复制地址
// 测试网：部署到 Sepolia 后，从 Etherscan 确认地址
export const FACTORY_ADDRESS = "0x...";

// 导出类型和工厂类，其他模块直接引用
export { MemeFactory__factory };
export type { MemeFactory };
```

**TypeChain 做了什么？**
- 分析合约 ABI，为每个 `function` 生成 TypeScript 方法签名（参数 + 返回值类型）
- 为每个 `event` 生成类型安全的事件过滤器
- `__factory` 类提供 `connect(address, provider/signer)` 方法，返回带类型的 Contract 实例

> **课堂提问**：为什么不用 JSON 文件手动导入 ABI（`import abi from "./MemeFactory.json"`）？
>
> **答案**：手动导入 JSON 时，合约方法都是 `any` 类型——调用 `factory.createToken(...)` 不会有参数类型提示，传错参数顺序或类型只能在运行时发现。TypeChain 是编译时生成的，有如下好处：
> - 参数拼写错误 → TypeScript 编译报错（而非生产环境才发现）
> - 返回值类型自动推断（`const fee: bigint = await factory.creationFee()`）
> - 合约升级后 ABI 变化 → 前端编译失败 → 强制开发者同步更新
> - 这实现了"合约是前端类型的单一真相源"

### 5.2 只读连接：查询合约数据（view 函数）

所有 `view` / `pure` 函数都不需要 gas，不需要用户签名，只需要 `provider`。

```typescript
// 文件：frontend/src/factory.ts（第1-25行）

import { BrowserProvider, Contract, formatEther } from "ethers";
import { MemeFactory__factory, FACTORY_ADDRESS } from "./config";
import type { MemeFactory } from "./config";

// 创建一个只读的合约连接
// provider 不需要用户签名 → 不会弹出 MetaMask 窗口
export function getFactoryReadOnly(provider: BrowserProvider): MemeFactory {
    return MemeFactory__factory.connect(FACTORY_ADDRESS, provider);
}

// ─── 下面是对应 MemeFactory.sol 各个查询函数的封装 ───

// 对应 contracts/MemeFactory.sol:112 totalTokens()
export async function getTotalTokens(factory: MemeFactory): Promise<number> {
    const total = await factory.totalTokens();
    return Number(total);
}

// 对应 contracts/MemeFactory.sol:20 creationFee()
export async function getCreationFee(factory: MemeFactory): Promise<{ fee: bigint; feeEth: string }> {
    const fee: bigint = await factory.creationFee();
    return {
        fee,
        feeEth: formatEther(fee),  // wei → ETH 显示（如 "0.01"）
    };
}

// 对应 contracts/MemeFactory.sol:124 getTokensPaginated(offset, limit)
// 返回值 tokens 是地址数组，total 是总数
export async function getTokensPaginated(
    factory: MemeFactory,
    offset: number,
    limit: number
): Promise<{ tokens: string[]; total: number }> {
    const result = await factory.getTokensPaginated(offset, limit);
    return {
        tokens: result.tokens,     // address[]
        total: Number(result.total), // uint256 → number
    };
}

// 对应 contracts/MemeFactory.sol:116 getTokensByCreator(creator)
export async function getTokensByCreator(
    factory: MemeFactory,
    creator: string
): Promise<string[]> {
    return factory.getTokensByCreator(creator);
}

// 对应 contracts/MemeFactory.sol:26 tokenParams 映射
// 返回单个代币的创建参数（名称、符号、供应量、税率等）
export async function getTokenParams(
    factory: MemeFactory,
    tokenAddress: string
): Promise<{
    name: string;
    symbol: string;
    totalSupply: bigint;
    buyTax: number;
    sellTax: number;
}> {
    const params = await factory.tokenParams(tokenAddress);
    return {
        name: params.name,
        symbol: params.symbol,
        totalSupply: params.totalSupply,
        buyTax: Number(params.buyTax),
        sellTax: Number(params.sellTax),
    };
}
```

**对号入座——前端函数 ↔ 合约函数对照表**：

| 前端函数（factory.ts） | 合约函数（MemeFactory.sol） | 行号 | 调用方式 |
|-----------------------|---------------------------|------|---------|
| `getTotalTokens()` | `totalTokens()` | 112 | view，免费 |
| `getCreationFee()` | `creationFee()` | 20 | view，免费 |
| `getTokensPaginated()` | `getTokensPaginated(offset, limit)` | 124-144 | view，免费 |
| `getTokensByCreator()` | `getTokensByCreator(creator)` | 116 | view，免费 |
| `getTokenParams()` | `tokenParams(tokenAddr)` | 26 (mapping) | view，免费 |

### 5.3 写入连接：发送创建代币交易（write 函数）

写操作需要 Signer，每次调用都会弹出 MetaMask 确认窗口。

```typescript
// 文件：frontend/src/factory.ts（第27-80行）

import { BrowserProvider, Contract, parseEther } from "ethers";

// 获取带签名能力的合约连接
// signer 由 BrowserProvider.getSigner() 生成 → 关联当前选中的 MetaMask 账户
export async function getFactoryWithSigner(provider: BrowserProvider): Promise<MemeFactory> {
    const signer = await provider.getSigner();
    return MemeFactory__factory.connect(FACTORY_ADDRESS, signer);
}

// ─── 创建代币的参数类型（与合约 TokenParams 结构体一一对应）───
// 对应 contracts/MemeFactory.sol:8-17 TokenParams 结构体
export interface CreateTokenParams {
    name: string;
    symbol: string;
    totalSupply: bigint;       // 注意：前端传 bigint，对应合约的 uint256
    marketingWallet: string;   // 0x 开头的 42 字符地址
    teamWallet: string;
    buyTax: bigint;            // 基点制，如 500 = 5%
    sellTax: bigint;
}

// ─── 核心：调用 createToken ───
// 对应 contracts/MemeFactory.sol:56-108 createToken(TokenParams) payable
export async function createToken(
    factory: MemeFactory,
    params: CreateTokenParams,
    creationFee: bigint
): Promise<{
    txHash: string;
    tokenAddress: string;
    blockNumber: number;
}> {
    // 步骤1：发送交易
    // ethers.js 自动将 CreateTokenParams 对象转换为合约的 TokenParams 结构体
    // { value: creationFee } 对应合约中的 msg.value
    const tx = await factory.createToken(params, { value: creationFee });

    console.log("交易已广播，等待确认...");
    console.log("  txHash:", tx.hash);
    // 此时交易处于 pending 状态，尚未上链

    // 步骤2：等待交易被矿工打包确认（默认等待 1 个区块）
    // tx.wait() 内部会轮询 eth_getTransactionReceipt
    const receipt = await tx.wait();
    console.log("交易已确认！");
    console.log("  blockNumber:", receipt.blockNumber);
    console.log("  gasUsed:", receipt.gasUsed.toString());

    // 步骤3：从交易收据中解析 TokenCreated 事件
    // 合约事件定义在 contracts/MemeFactory.sol:35-44
    // event TokenCreated(
    //     address indexed tokenAddress,   // ← 这是我们需要的
    //     address indexed creator,
    //     string name,
    //     string symbol,
    //     uint256 totalSupply,
    //     uint256 buyTax,
    //     uint256 sellTax,
    //     uint256 index
    // );
    let tokenAddress = "";

    // receipt.logs 包含了这笔交易触发的所有事件日志
    for (const log of receipt.logs) {
        try {
            // factory.interface.parseLog 将原始日志解析为结构化数据
            const parsed = factory.interface.parseLog({
                topics: log.topics as string[],
                data: log.data,
            });
            if (parsed && parsed.name === "TokenCreated") {
                tokenAddress = parsed.args.tokenAddress;
                console.log("  新代币地址:", tokenAddress);
                break;
            }
        } catch {
            // 不是我们关心的日志，跳过
            continue;
        }
    }

    if (!tokenAddress) {
        throw new Error("交易成功但未能解析出代币地址");
    }

    return {
        txHash: tx.hash,
        tokenAddress,
        blockNumber: receipt.blockNumber,
    };
}
```

> **课堂提问**：为什么从 `receipt.logs` 中解析事件，而不是直接让 `createToken` 返回代币地址？
>
> **答案**：回顾 `contracts/MemeFactory.sol:56`，`createToken` 的返回值确实是 `returns (address)`。但在 ethers.js 中，**写入函数的返回值不会返回给调用者**——这是因为交易是异步的，函数在未来的某个区块中执行，当前无法立即获取返回值。要获取写入函数的返回值，有两种方式：（1）像本课这样从 receipt.logs 中解析事件；（2）使用 `callStatic` 模拟执行。事件解析是更可靠的生产级方案，因为事件是链上永久记录，任何人可验证。

### 5.4 错误处理模块

```typescript
// 文件：frontend/src/factory.ts（第82-115行）

// 用户可见的错误类型
export enum TxErrorType {
    USER_REJECTED = "USER_REJECTED",   // 用户在 MetaMask 点了拒绝
    CONTRACT_REVERT = "CONTRACT_REVERT", // 合约 require/revert 触发
    INSUFFICIENT_FUNDS = "INSUFFICIENT_FUNDS", // 余额不足
    NETWORK_ERROR = "NETWORK_ERROR",   // 网络问题
    UNKNOWN = "UNKNOWN",
}

export interface TxError {
    type: TxErrorType;
    message: string;  // 用户可读的中文提示
}

// 统一的交易错误处理
export function parseTransactionError(err: any): TxError {
    // 情况1：用户在 MetaMask 中拒绝签名/确认
    // ethers.js v6 的错误码是 "ACTION_REJECTED"，MetaMask 原生错误码是 4001
    if (err.code === "ACTION_REJECTED" || err.code === 4001) {
        return {
            type: TxErrorType.USER_REJECTED,
            message: "用户取消了交易",
        };
    }

    // 情况2：合约执行 revert（require 条件不满足）
    // ethers.js v6 将 revert reason 放在 err.reason 或 err.shortMessage 中
    if (err.reason || err.shortMessage) {
        const reason = err.reason || err.shortMessage;
        // 常见 revert 原因及其用户友好的中文翻译
        const reasonMap: Record<string, string> = {
            "insufficient creation fee": "创建费用不足，请检查余额",
            "invalid name length": "代币名称长度不符合要求（1-32 字符）",
            "invalid symbol length": "代币符号长度不符合要求（1-8 字符）",
            "supply out of range": "供应量超出范围（1,000 ~ 1,000,000,000,000）",
            "zero marketing wallet": "营销钱包地址不能为零地址",
            "zero team wallet": "团队钱包地址不能为零地址",
            "tax too high": "税率不能超过 25%（2500 基点）",
        };
        return {
            type: TxErrorType.CONTRACT_REVERT,
            message: reasonMap[reason] || `合约执行失败: ${reason}`,
        };
    }

    // 情况3：余额不足支付 gas 或 value
    if (err.message && err.message.includes("insufficient funds")) {
        return {
            type: TxErrorType.INSUFFICIENT_FUNDS,
            message: "账户余额不足，无法支付创建费用和 Gas 费",
        };
    }

    // 情况4：未知错误
    return {
        type: TxErrorType.UNKNOWN,
        message: `发生未知错误: ${err.message || "请重试"}`,
    };
}
```

**错误码速查表**：

| 错误码 | 来源 | 含义 | 建议处理 |
|--------|------|------|---------|
| `ACTION_REJECTED` | ethers.js v6 | 用户拒绝交易 | 静默恢复 UI，不显示错误 |
| `4001` | MetaMask (EIP-1193) | 用户拒绝请求 | 同上 |
| `CALL_EXCEPTION` | ethers.js v6 | 合约调用失败 | 显示 err.reason 中的 revert 原因 |
| `UNPREDICTABLE_GAS_LIMIT` | ethers.js v6 | gas 估算失败 | 通常意味着交易一定会 revert，检查参数 |
| `INSUFFICIENT_FUNDS` | ethers.js v6 | 余额不足 | 提示用户充值或降低金额 |
| `NETWORK_ERROR` | ethers.js v6 | RPC 连接失败 | 提示检查网络或刷新页面 |
| `-32603` | JSON-RPC | 内部错误 | 通常是 gas 估算失败或 nonce 冲突 |

### 5.5 安全的交易包装函数

```typescript
// 文件：frontend/src/factory.ts（第117-140行）

// 带统一错误处理的交易执行包装
export async function safeExecuteTx<T>(
    fn: () => Promise<T>,
    onError: (error: TxError) => void
): Promise<T | null> {
    try {
        return await fn();
    } catch (err: any) {
        const txError = parseTransactionError(err);

        // 用户拒绝不算错，不显示错误提示
        if (txError.type === TxErrorType.USER_REJECTED) {
            return null;
        }

        onError(txError);
        return null;
    }
}

// 文件：frontend/src/ui.ts（校验部分，第1-80行）

// ─── 校验规则类型 ───
interface ValidationRule {
    fieldId: string;  // 对应 input 元素的 id
    validate: (value: string) => string | null;
    // 返回 null = 通过，返回 string = 错误信息
}

// ─── 校验规则定义（与合约约束一一对应）───
const VALIDATION_RULES: ValidationRule[] = [
    // 名称：对应 contracts/MemeFactory.sol:61-62
    {
        fieldId: "name",
        validate: (v) => {
            if (!v.trim()) return "名称不能为空";
            if (v.trim().length > 32) return "名称不能超过 32 个字符";
            return null;
        },
    },
    // 符号：对应 contracts/MemeFactory.sol:64-65
    {
        fieldId: "symbol",
        validate: (v) => {
            if (!v.trim()) return "符号不能为空";
            if (!/^[A-Z]{3,8}$/.test(v)) return "符号必须为 3-8 个大写英文字母";
            return null;
        },
    },
    // 供应量：对应 contracts/MemeFactory.sol:67-69
    {
        fieldId: "supply",
        validate: (v) => {
            const n = Number(v);
            if (isNaN(n) || !Number.isInteger(n)) return "请输入整数";
            if (n < 1000) return "供应量不能小于 1,000";
            if (n > 1_000_000_000_000) return "供应量不能大于 1,000,000,000,000";
            return null;
        },
    },
    // 营销钱包：对应 contracts/MemeFactory.sol:71
    {
        fieldId: "marketing",
        validate: (v) => {
            if (!/^0x[0-9a-fA-F]{40}$/.test(v)) return "请输入有效的以太坊地址";
            if (v === "0x0000000000000000000000000000000000000000") return "不能为零地址";
            return null;
        },
    },
    // 团队钱包：对应 contracts/MemeFactory.sol:72
    {
        fieldId: "team",
        validate: (v) => {
            if (!/^0x[0-9a-fA-F]{40}$/.test(v)) return "请输入有效的以太坊地址";
            if (v === "0x0000000000000000000000000000000000000000") return "不能为零地址";
            return null;
        },
    },
    // 买入税：对应 contracts/MemeFactory.sol:73 buyTax <= 2500
    {
        fieldId: "buy-tax",
        validate: (v) => {
            const n = Number(v);
            if (isNaN(n) || !Number.isInteger(n)) return "请输入整数";
            if (n < 0 || n > 2500) return "税率范围为 0 ~ 2500 基点（0% ~ 25%）";
            return null;
        },
    },
    // 卖出税：对应 contracts/MemeFactory.sol:73 sellTax <= 2500
    {
        fieldId: "sell-tax",
        validate: (v) => {
            const n = Number(v);
            if (isNaN(n) || !Number.isInteger(n)) return "请输入整数";
            if (n < 0 || n > 2500) return "税率范围为 0 ~ 2500 基点（0% ~ 25%）";
            return null;
        },
    },
];

// ─── 执行全量校验 → 返回 Map<字段ID, 错误信息> ───
export function validateForm(): Map<string, string> {
    const errors = new Map<string, string>();
    for (const rule of VALIDATION_RULES) {
        const input = document.getElementById(`input-${rule.fieldId}`) as HTMLInputElement;
        if (!input) continue;
        const error = rule.validate(input.value);
        if (error) {
            errors.set(rule.fieldId, error);
        }
    }
    return errors;
}

// ─── 实时校验绑定（在 input/blur 事件时触发）───
export function setupRealTimeValidation(): void {
    for (const rule of VALIDATION_RULES) {
        const input = document.getElementById(`input-${rule.fieldId}`) as HTMLInputElement;
        if (!input) continue;

        // 失焦时校验
        input.addEventListener("blur", () => {
            const error = rule.validate(input.value);
            showFieldError(rule.fieldId, error);
        });

        // 输入时清除错误（用户体验优化）
        input.addEventListener("input", () => {
            clearFieldError(rule.fieldId);
        });
    }
}

// ─── 显示/清除单个字段的错误提示 ───
function showFieldError(fieldId: string, error: string | null): void {
    const errorEl = document.querySelector(`.error-msg[data-for="${fieldId}"]`);
    const inputEl = document.getElementById(`input-${fieldId}`);
    if (errorEl) errorEl.textContent = error || "";
    if (inputEl) {
        inputEl.classList.toggle("invalid", !!error);
        inputEl.classList.toggle("valid", !error);
    }
}

function clearFieldError(fieldId: string): void {
    showFieldError(fieldId, null);
}
```

### 6.3 前端校验 vs 合约校验 —— 三层防御体系

```
第1层：HTML 原生校验（免费、即时、无 JS 依赖）
  ├── maxlength / minlength（字符长度限制）
  ├── pattern 正则（地址格式、符号格式）
  ├── min / max（数值范围）
  └── required（必填项）

第2层：TypeScript 校验（自定义逻辑、更友好的错误提示）
  ├── validateForm() 全量校验
  ├── 实时反馈（blur 事件触发）
  └── 错误信息中文化

第3层：Solidity 合约校验（不可绕过的安全屏障）
  ├── contracts/MemeFactory.sol:57   require(msg.value >= creationFee)
  ├── contracts/MemeFactory.sol:61-62  bytes(name).length 校验
  ├── contracts/MemeFactory.sol:64-65  bytes(symbol).length 校验
  ├── contracts/MemeFactory.sol:67-69  totalSupply 范围校验
  ├── contracts/MemeFactory.sol:71-72  wallet 非零校验
  └── contracts/MemeFactory.sol:73   tax <= 2500 校验
```

> **课堂提问**：既然合约已经有完整的校验逻辑，为什么前端还需要校验？
>
> **答案**：（1）**成本**：合约校验需要用户支付 gas 发起交易，如果参数不合法，交易虽然会 revert 但 gas 不退。前端校验免费且即时。（2）**体验**：前端校验在用户输入时就能给出反馈（毫秒级），合约校验需要等交易执行完才知道（数秒到数十秒）。（3）**安全分层**：前端校验可以被绕过（比如用 curl 直接调 RPC），但合约校验是不可绕过的。两者是互补关系，不是替代关系。**核心原则**：前端校验是用户体验优化，合约校验是安全底线。永远不要因为前端有校验就删掉合约校验。

## 七、代币列表页实现 —— `frontend/src/ui.ts`（15 分钟）

### 7.1 分页加载

分页查询调用的是 `contracts/MemeFactory.sol:124-144` 的 `getTokensPaginated`。该函数实现了经典的 `offset + limit` 模式，避免了在一次调用中返回全量数据导致 gas 超限。

```typescript
// 文件：frontend/src/ui.ts（列表部分，第162-195行）

const PAGE_SIZE = 10;  // 每页10条
let currentPage = 0;
let totalTokens = 0;

export async function loadTokenList(
    factory: MemeFactory,
    page: number
): Promise<void> {
    const offset = page * PAGE_SIZE;

    // 调用 contracts/MemeFactory.sol:124 getTokensPaginated
    // 合约源码的分页逻辑（第131-143行）：
    //   if (_offset >= total) return (new address[](0), total);
    //   uint256 end = _offset + _limit;
    //   if (end > total) end = total;  // 防止越界
    //   for (uint256 i = 0; i < tokens.length; i++) {
    //       tokens[i] = allTokens[_offset + i];
    //   }
    const { tokens, total } = await getTokensPaginated(factory, offset, PAGE_SIZE);

    totalTokens = total;
    currentPage = page;

    // 渲染表格
    await renderTokenTable(factory, tokens);

    // 渲染分页控件
    const totalPages = Math.max(1, Math.ceil(totalTokens / PAGE_SIZE));
    renderPagination(page, totalPages);

    // 更新信息栏
    document.getElementById("list-info")!.textContent =
        `共 ${totalTokens} 个代币，第 ${page + 1}/${totalPages} 页`;
}
```

### 7.2 渲染代币表格

```typescript
// 文件：frontend/src/ui.ts（渲染部分，第197-245行）

async function renderTokenTable(
    factory: MemeFactory,
    tokens: string[]
): Promise<void> {
    const tbody = document.querySelector("#token-table tbody")!;
    tbody.innerHTML = "";

    if (tokens.length === 0) {
        tbody.innerHTML = `<tr><td colspan="4" class="empty">暂无代币，成为第一个创建者！</td></tr>`;
        return;
    }

    // 每个代币需要额外查询参数 → 并行请求（Promise.all）
    const paramPromises = tokens.map(addr => getTokenParams(factory, addr));
    const allParams = await Promise.all(paramPromises);

    for (let i = 0; i < tokens.length; i++) {
        const addr = tokens[i];
        const params = allParams[i];

        const row = document.createElement("tr");
        row.innerHTML = `
            <td>
                <span class="token-name">${escapeHtml(params.name)}</span>
                <span class="token-symbol">(${escapeHtml(params.symbol)})</span>
            </td>
            <td>${formatEther(params.totalSupply)}</td>
            <td>
                <span class="tax-badge">买 ${(params.buyTax / 100).toFixed(2)}%</span>
                <span class="tax-badge">卖 ${(params.sellTax / 100).toFixed(2)}%</span>
            </td>
            <td>
                <a href="https://sepolia.etherscan.io/address/${addr}"
                   target="_blank" class="addr-link" title="${addr}">
                    ${shortAddr(addr)}
                </a>
            </td>
        `;
        tbody.appendChild(row);
    }
}

// ─── 地址缩短显示（如 0x1234...abcd）───
function shortAddr(addr: string): string {
    return `${addr.slice(0, 6)}...${addr.slice(-4)}`;
}

// ─── XSS 防护：用户输入的代币名称必须转义 ───
function escapeHtml(text: string): string {
    const div = document.createElement("div");
    div.textContent = text;  // 不会解析 HTML 标签
    return div.innerHTML;
}
```

> **课堂提问**：为什么 `escapeHtml` 是必须的？不转义会有什么后果？
>
> **答案**：代币名称由用户在表单中输入，理论上可以包含任意内容，包括 `<script>alert('XSS')</script>`。如果直接拼接到 `innerHTML` 中不做转义，这段脚本就会在访问代币列表页的每个用户浏览器中执行。攻击者可以：
> - 窃取其他用户的 MetaMask 连接信息
> - 伪造交易确认弹窗诱导用户签名
> - 将用户重定向到钓鱼网站
>
> `textContent` 赋值会自动将 `<script>` 等特殊字符转义为文本（`&lt;script&gt;`），从而安全地渲染任意用户输入。**核心原则：所有链上用户输入数据在渲染到 DOM 时都必须转义。**

### 7.3 分页控件渲染

```typescript
// 文件：frontend/src/ui.ts（分页部分，第247-290行）

function renderPagination(current: number, totalPages: number): void {
    const nav = document.getElementById("pagination")!;
    nav.innerHTML = "";

    if (totalPages <= 1) return;

    // 上一页按钮
    nav.appendChild(createPageBtn("← 上一页", current > 0, () => {
        loadTokenList(factory, current - 1);
    }));

    // 页码按钮（最多显示 7 个页码，带省略号）
    const visiblePages = getVisiblePages(current, totalPages);
    for (const pageNum of visiblePages) {
        if (pageNum === -1) {
            nav.appendChild(createPageEllipsis());
        } else {
            const isActive = pageNum === current;
            nav.appendChild(createPageBtn(
                String(pageNum + 1),
                !isActive,
                () => loadTokenList(factory, pageNum),
                isActive
            ));
        }
    }

    // 下一页按钮
    nav.appendChild(createPageBtn("下一页 →", current < totalPages - 1, () => {
        loadTokenList(factory, current + 1);
    }));
}

// 智能页码：总是显示首尾页，当前页附近显示 3 个
// 例如：[1] ... [4] [5] [6] ... [20]
function getVisiblePages(current: number, total: number): number[] {
    if (total <= 7) {
        // 总页数少，全部显示
        return Array.from({ length: total }, (_, i) => i);
    }

    const pages: number[] = [0]; // 首页

    const start = Math.max(1, current - 1);
    const end = Math.min(total - 2, current + 1);

    if (start > 1) pages.push(-1); // ... 省略号
    for (let i = start; i <= end; i++) pages.push(i);
    if (end < total - 2) pages.push(-1); // ... 省略号

    pages.push(total - 1); // 末页
    return pages;
}

function createPageBtn(
    label: string,
    enabled: boolean,
    onClick: () => void,
    isActive: boolean = false
): HTMLButtonElement {
    const btn = document.createElement("button");
    btn.textContent = label;
    btn.disabled = !enabled;
    btn.className = "page-btn";
    if (isActive) btn.classList.add("active");
    if (enabled) btn.addEventListener("click", onClick);
    return btn;
}

function createPageEllipsis(): HTMLSpanElement {
    const span = document.createElement("span");
    span.textContent = "...";
    span.className = "page-ellipsis";
    return span;
}
```

## 九、总结与安全要点（5 分钟）

| 类别 | 要点 | 对应代码位置 |
|------|------|-------------|
| 架构分层 | Provider（只读）与 Signer（写入）分离 | `wallet.ts:10-28`、`factory.ts:1-5` |
| 权限模型 | `eth_requestAccounts`（弹窗）vs `eth_accounts`（静默） | `wallet.ts:10-18` |
| 事件解析 | 写入函数返回值不可用，必须从 receipt.logs 解析事件 | `factory.ts:27-80` |
| 三层校验 | HTML 原生 → TypeScript 自定义 → Solidity require | `index.html` → `ui.ts` → `MemeFactory.sol:57-73` |
| XSS 防护 | 所有链上用户输入渲染到 DOM 前必须 `escapeHtml` | `ui.ts:237-241` |
| 错误分类 | 用户拒绝 ≠ 合约 revert ≠ 余额不足 ≠ 网络错误 | `factory.ts:82-115` |
| 状态同步 | `accountsChanged` 更新 UI，`chainChanged` 重载页面 | `wallet.ts:30-48` |
| 类型安全 | TypeChain 确保前端调用与合约 ABI 编译时同步 | `config.ts:1-10` |
| 交易反馈 | pending → confirmed → 结果解析，三个阶段都要 UI 反馈 | `ui.ts:82-160` |
| 依赖隔离 | 合约工具链与前端依赖分属不同 `package.json` | 根 `package.json` vs `frontend/package.json` |
