## 二、知识回顾（5 分钟）

**Q1：`hardhat.config.ts` 中的 `networks` 配置是如何工作的？为什么需要 `PRIVATE_KEY`？**

> 答案：`hardhat.config.ts:17-31`。Hardhat 在运行脚本时读取 `networks` 配置，每个网络条目指定了 RPC URL 和签名账户。`PRIVATE_KEY` 是 EOA 的私钥——Hardhat 用它在链上签署部署交易。没有私钥，你只能做 `view` 调用，无法发送交易。
>
> 关键设计：只有 `PRIVATE_KEY` 格式正确（64位十六进制）时才添加 Sepolia 网络，防止格式错误的配置导致交易失败。

**Q2：部署 MemeToken 后还需要哪些步骤才能开始交易？**

> 答案：完整的部署后流程（`scripts/setup_uniswap.ts:68-106`）：
> 1. `setUniswapRouter(router)` —— 设置 Uniswap 路由地址
> 2. `Factory.createPair(token, WETH)` —— 创建交易对
> 3. `setUniswapPair(pair)` —— 设置 Pair（自动排除交易限制）
> 4. `enableTrading()` —— 开启交易
> 5. （本课新增）`lockRouter()` —— 锁定 Router，防止被篡改

**Q3：为什么 MemeFactory 创建代币后要 `newToken.transferOwnership(msg.sender)`？**

> 答案：因为 `new MemeToken(...)` 的构造函数执行 `Ownable(msg.sender)`，此时 `msg.sender` 是 Factory 合约地址。如果创建后不转移所有权，创建者无法管理自己的代币——Factory 会变成 owner。这是一个所有权传递链路的典型问题。

**引入**：前三问指向一个现实——部署不是 `npx hardhat run` 就结束了。真正的生产部署涉及网络选择、多合约编排、部署后配置、状态追踪和验证。本课将建立一套完整的部署系统。

## 三、部署脚本架构设计（15 分钟）

### 3.1 单合约 vs. 多合约部署

```
单合约部署（scripts/deploy.ts）：
  deploy() → waitForDeployment() → console.log(address)
  
  适用场景：演示、单合约项目
  问题：无法处理合约间依赖、没有状态追踪、重复部署会覆盖

多合约编排（本课）：
  deploy Factory
    → deploy Token (via Factory or direct)
      → setRouter + setPair + enableTrading + lockRouter
        → deploy Locker
          → deploy FairLaunch
            → save all addresses to deployments/<network>.json
              → verify all contracts on Etherscan
```

### 3.2 部署脚本的模块化设计

```
scripts/
├── deploy.ts                  # 基础示例（HelloMeme）
├── deploy_meme.ts             # MemeToken 单合约部署
├── deploy_standard.ts         # StandardMemeToken 部署
├── setup_uniswap.ts           # Uniswap 初始化脚本
├── deploy_all.ts              # ✨ 本课核心：完整部署流水线
└── helpers/
    ├── network.ts             # 网络配置管理
    └── state.ts               # 部署状态持久化
```

**设计原则**：

| 原则 | 说明 | 反例 |
|------|------|------|
| 单一职责 | 每个函数只做一件事 | 一个函数既部署又验证又保存状态 |
| 可重入 | 任何步骤失败可重试（检查已有状态） | 失败后需全部重新部署 |
| 网络无关 | 同一份代码适配所有网络 | 为每个网络写一份脚本 |
| 可追踪 | 每次部署记录地址 + 时间戳 | 部署后靠人工记录地址 |

### 3.3 部署脚本的基本结构

```typescript
// scripts/deploy_all.ts —— 核心框架
async function main() {
  // 1. 获取签名者
  const [deployer] = await ethers.getSigners();
  
  // 2. 检测网络
  const network = await detectNetwork();
  console.log(`部署网络: ${network.name} (chainId: ${network.chainId})`);
  
  // 3. 部署前检查
  await preflightCheck(deployer, network);
  
  // 4. 执行部署流水线
  const factory = await deployOrConnectFactory(deployer);
  const token = await deployToken(factory, deployer, params);
  await setupUniswap(token, deployer, network);
  await deployLocker(token, deployer);
  
  // 5. 保存部署状态
  await saveDeployment(network.name, { factory, token, locker, timestamp });
  
  // 6. 输出摘要
  printSummary(network, deployedAddresses);
}
```

### 4.1 为什么需要多网络？

```
Localhost (hardhat node)
  → 本地开发测试
```

```typescript
    factory: "0x5C69bEe701ef814a2B6a3EDD4B1652CB9cc5aA6f",

  },

interface NetworkInfo {
  name: string;
  chainId: number;
  isTestnet: boolean;
  uniswapV2Factory: string;
  uniswapV2Router: string;
}

async function detectNetwork(): Promise<NetworkInfo> {
  const { chainId } = await ethers.provider.getNetwork();
  const uni = UNISWAP_ADDRESSES[Number(chainId)];
  if (!uni) throw new Error(`不支持的链 ID: ${chainId}`);
  
  return {
    chainId: Number(chainId),
    name: chainId === 1n ? "mainnet" : chainId === 11155111n ? "sepolia" : "hardhat",
    isTestnet: chainId !== 1n,
    uniswapV2Factory: uni.factory,
    uniswapV2Router: uni.router,
  };
}
```

**关键设计决策**：

| 决策 | 选项 | 本课选择 | 原因 |
|------|------|---------|------|
| 配置存储位置 | `.ts` 文件 / `.json` 文件 / `.env` | `.ts` 文件 | TypeScript 类型安全 + IDE 自动补全 |
| 网络识别方式 | chainId / network name | chainId | chainId 是不可变的链标识；name 可被篡改 |
| 地址来源 | 硬编码 / 链上查询 | 硬编码 + 链上验证 | 硬编码避免重复 RPC 调用；部署后从事件解析 |

### 5.2 部署前检查（Preflight Check）

```typescript
// scripts/deploy_all.ts

interface DeployParams {
  tokenName: string;
  tokenSymbol: string;
  totalSupply: number;
  buyTax: number;
  sellTax: number;
  feeReceiver: string;
  creationFee: string;    // ETH，例如 "0.01"
  lockDuration: number;   // 秒
}

async function preflightCheck(
  deployer: SignerWithAddress,
  network: NetworkInfo
): Promise<void> {
  const balance = await ethers.provider.getBalance(deployer.address);
  const minBalance = network.isTestnet
    ? ethers.parseEther("0.1")
    : ethers.parseEther("0.5");

  console.log(`  Deployer:       ${deployer.address}`);
  console.log(`  ETH Balance:    ${ethers.formatEther(balance)} ETH`);

  // 检查 1：ETH 余额
  if (balance < minBalance) {
    throw new Error(
      `ETH 余额不足！当前: ${ethers.formatEther(balance)}, 最少需要: ${ethers.formatEther(minBalance)}`
    );
  }

  // 检查 2：RPC 可用性
  try {
    const blockNumber = await ethers.provider.getBlockNumber();
    console.log(`  当前区块高度:   ${blockNumber}`);
  } catch {
    throw new Error("RPC 不可用，请检查网络配置");
  }

  // 检查 3：Gas Price（主网尤其重要）
  const feeData = await ethers.provider.getFeeData();
  if (feeData.gasPrice) {
    const gasGwei = ethers.formatUnits(feeData.gasPrice, "gwei");
    console.log(`  当前 Gas Price: ${gasGwei} gwei`);
    if (!network.isTestnet && feeData.gasPrice > ethers.parseUnits("100", "gwei")) {
      console.warn("  ⚠️ Gas Price 高于 100 gwei，建议等待降低后再部署");
    }
  }

  // 检查 4：非零地址
  if (!ethers.isAddress(DEPLOY_PARAMS.feeReceiver)) {
    throw new Error("feeReceiver 不是有效地址");
  }

  console.log("  部署前检查通过 ✓\n");
}
```

### 5.3 Factory 部署（可重入）

```typescript
// scripts/deploy_all.ts

async function deployOrConnectFactory(
  deployer: SignerWithAddress,
  network: NetworkInfo
): Promise<MemeFactory> {
  // 检查是否已部署
  const existing = loadDeployment(network.name);
  if (existing?.factory) {
    console.log(`Factory 已部署: ${existing.factory}`);
    return ethers.getContractAt("MemeFactory", existing.factory) as unknown as MemeFactory;
  }

  console.log("部署 MemeFactory...");
  const Factory = await ethers.getContractFactory("MemeFactory");
  const creationFee = ethers.parseEther(DEPLOY_PARAMS.creationFee);
  const factory = await Factory.deploy(creationFee);
  await factory.waitForDeployment();

  const addr = await factory.getAddress();
  console.log(`  MemeFactory:  ${addr}`);
  console.log(`  CreationFee:  ${ethers.formatEther(creationFee)} ETH`);
  return factory as unknown as MemeFactory;
}
```

**关键设计：可重入性**。如果部署失败（如 gas 不足），重新运行脚本应跳过已部署的合约。通过检查 `deployments/<network>.json` 实现。

### 5.4 Token 创建与 Uniswap 初始化

通过 Factory 创建代币的优势：
- Factory 自动处理所有权转移（`transferOwnership(creator)`）
- 代币自动记录到 Factory 的 `allTokens` 列表
- 前端可通过 Factory 查询所有已创建代币

```typescript
async function deployToken(
  factory: MemeFactory,
  deployer: SignerWithAddress,
  network: NetworkInfo
): Promise<{ token: MemeToken; address: string }> {
  const existing = loadDeployment(network.name);
  if (existing?.token) {
    console.log(`Token 已部署: ${existing.token}`);
    const token = await ethers.getContractAt("MemeToken", existing.token);
    return { token: token as unknown as MemeToken, address: existing.token };
  }

  const p = DEPLOY_PARAMS;
  console.log(`通过 Factory 创建代币: ${p.tokenName} (${p.tokenSymbol})`);

  const tx = await factory.createToken(
    p.tokenName, p.tokenSymbol, p.totalSupply,
    p.feeReceiver, p.feeReceiver,  // marketing, team
    p.buyTax, p.sellTax,
    { value: ethers.parseEther(p.creationFee) }
  );
  const receipt = await tx.wait();
  if (!receipt || receipt.status !== 1) throw new Error("Token creation failed");

  // 从事件中解析代币地址
  const tokenAddr = await factory.createdTokens(
    await factory.allTokens(await factory.allTokensLength() - 1n)
  );
  const token = await ethers.getContractAt("MemeToken", tokenAddr);

  console.log(`  Token:        ${tokenAddr}`);
  console.log(`  TotalSupply:  ${ethers.formatEther(await token.totalSupply())}`);
  return { token: token as unknown as MemeToken, address: tokenAddr };
}
```

### 5.5 Uniswap 集成初始化

```typescript
async function setupUniswap(
  token: MemeToken,
  deployer: SignerWithAddress,
  network: NetworkInfo
): Promise<void> {
  // 检查 Router 是否已设置
  const existingRouter = await token.uniswapV2Router();
  if (existingRouter !== ethers.ZeroAddress) {
    console.log(`Router 已设置: ${existingRouter}`);
    if (await token.tradingEnabled()) {
      console.log("  交易已启用，跳过 Uniswap 初始化");
      return;
    }
  }

  // Step 1: 设置 Router
  console.log(`设置 Uniswap Router: ${network.uniswapV2Router}`);
  await (token.setUniswapRouter(network.uniswapV2Router) as any).then(tx => tx.wait());

  // Step 2: 创建 Pair
  const factoryContract = new ethers.Contract(
    network.uniswapV2Factory,
    ["function createPair(address,address) returns (address)"],
    deployer
  );
  const weth = await (new ethers.Contract(
    network.uniswapV2Router,
    ["function WETH() view returns (address)"],
    deployer
  )).WETH();
  
  const tokenAddr = await token.getAddress();
  let pairAddr = await factoryContract.getPair(tokenAddr, weth);
  if (pairAddr === ethers.ZeroAddress) {
    const tx = await factoryContract.createPair(tokenAddr, weth);
    await tx.wait();
    pairAddr = await factoryContract.getPair(tokenAddr, weth);
    console.log(`  Pair 已创建:  ${pairAddr}`);
  } else {
    console.log(`  Pair 已存在:  ${pairAddr}`);
  }

  // Step 3: 设置 Pair
  await (token.setUniswapPair(pairAddr) as any).then(tx => tx.wait());
  console.log("  Pair 已设置 ✓");

  // Step 4: 启用交易
  await (token.enableTrading() as any).then(tx => tx.wait());
  console.log("  交易已启用 ✓");

  // Step 5: 锁定 Router（第13课安全修复）
  await (token.lockRouter() as any).then(tx => tx.wait());
  console.log("  Router 已锁定 ✓");
}
```

## 六、合约验证（15 分钟）

### 6.1 为什么验证合约？

1. **透明性**：用户在 Etherscan 上可以看到合约源码
2. **可交互性**：验证后才能通过 Etherscan 直接调用合约函数
3. **信任**：验证的合约比未验证的合约更可信
4. **Debug**：验证后的合约可以看到内部交易详情

### 6.2 Hardhat 验证配置

```typescript
// hardhat.config.ts:44-46
etherscan: {
  apiKey: ETHERSCAN_API_KEY || "",
},
```

**验证命令**：

```bash
# 无构造函数参数
npx hardhat verify --network sepolia <CONTRACT_ADDRESS>

# 有构造函数参数
npx hardhat verify --network sepolia <CONTRACT_ADDRESS> \
  "TokenName" "SYMBOL" 1000000 \
  "0xMarketingWallet" "0xTeamWallet" 300 500

# MemeFactory 验证
npx hardhat verify --network sepolia <FACTORY_ADDRESS> \
  "10000000000000000"  # 0.01 ETH in wei
```

### 6.3 自动化验证脚本

```typescript
// scripts/deploy_all.ts —— 自动验证
async function verifyContract(
  address: string,
  constructorArgs: any[],
  networkName: string
): Promise<void> {
  if (networkName === "hardhat") {
    console.log("  Hardhat 网络跳过验证");
    return;
  }

  console.log(`  验证合约: ${address}`);
  try {
    await hre.run("verify:verify", {
      address,
      constructorArguments: constructorArgs,
      network: networkName,
    });
    console.log("  验证成功 ✓");
  } catch (error: any) {
    if (error.message.includes("Already Verified")) {
      console.log("  合约已验证");
    } else {
      console.warn(`  验证失败: ${error.message}`);
    }
  }
}
```

**验证时机**：Etherscan 需要部署交易被确认后才能验证。在主网上建议等待 3-5 个区块确认后再验证。

### 6.4 常见验证问题

| 错误 | 原因 | 解决方案 |
|------|------|---------|
| `Already Verified` | 合约已验证 | 无需操作 |
| `Bytecode doesn't match` | 构造函数参数错误或编译器版本不匹配 | 检查 `solc` 版本和构造参数顺序 |
| `Contract not found` | 交易尚未被 Etherscan 索引 | 等待 30 秒后重试 |
| `API rate limit` | Etherscan API 频率限制 | 等待后重试或升级 API Key |
| `Reverted` | 合约部署失败 | 检查部署交易的 status |

```typescript
import * as fs from "fs";
import * as path from "path";

const DEPLOYMENTS_DIR = path.join(__dirname, "..", "deployments");

interface DeploymentRecord {
  contract: string;
  address: string;
  txHash: string;
  deployer: string;
  timestamp: string;
  constructorArgs?: any[];
}

interface DeploymentFile {
  network: string;
  chainId: number;
  lastUpdated: string;
  deployments: DeploymentRecord[];
}

function getDeploymentPath(network: string): string {
  return path.join(DEPLOYMENTS_DIR, `${network}.json`);
}

function loadDeployment(network: string): DeploymentFile | null {
  const filePath = getDeploymentPath(network);
  if (!fs.existsSync(filePath)) return null;
  return JSON.parse(fs.readFileSync(filePath, "utf8"));
}

function saveDeployment(network: string, record: DeploymentRecord): void {
  if (!fs.existsSync(DEPLOYMENTS_DIR)) {
    fs.mkdirSync(DEPLOYMENTS_DIR, { recursive: true });
  }

  const filePath = getDeploymentPath(network);
  let file: DeploymentFile = loadDeployment(network) || {
    network,
    chainId: 0,
    lastUpdated: new Date().toISOString(),
    deployments: [],
  };

  // 更新或添加记录
  const idx = file.deployments.findIndex(d => d.contract === record.contract);
  if (idx >= 0) {
    file.deployments[idx] = record;
  } else {
    file.deployments.push(record);
  }

  file.lastUpdated = new Date().toISOString();
  fs.writeFileSync(filePath, JSON.stringify(file, null, 2), "utf8");
  console.log(`部署状态已保存: ${filePath}`);
}
```

### 7.3 部署状态文件的生命周期

```
[部署开始] → [读取 deployments/<network>.json]
    │
    ├── 文件不存在 → 全新部署
    │       └── 部署所有合约 → 写入文件
    │
    └── 文件存在 → 检查已有地址
            ├── 合约已部署 → 跳过
            │       └── 连接已有合约 → 继续后续步骤
            └── 合约未部署 → 部署
                    └── 追加到文件
```

### 8.2 私钥安全管理

```
  方案 3：使用多签（Gnosis Safe）—— 需要多人确认
```

### 8.3 部署参数验证

```typescript
// 参数约束验证
function validateDeployParams(params: DeployParams): void {
  if (params.tokenName.length === 0 || params.tokenName.length > 32) {
    throw new Error("代币名长度必须在 1-32 之间");
  }
  if (params.tokenSymbol.length === 0 || params.tokenSymbol.length > 10) {
    throw new Error("代币符号长度必须在 1-10 之间");
  }
  if (params.buyTax > 2500 || params.sellTax > 2500) {
    throw new Error("税率不能超过 25%");
  }
  if (params.totalSupply < 1000 || params.totalSupply > 1_000_000_000) {
    throw new Error("总供应量必须在 1000 - 10 亿之间");
  }
  if (!ethers.isAddress(params.feeReceiver)) {
    throw new Error("feeReceiver 地址无效");
  }
  if (Number(params.creationFee) < 0.001 || Number(params.creationFee) > 1) {
    throw new Error("创建费用应在 0.001-1 ETH 之间");
  }
}
```

### 8.4 干跑（Dry Run）模式

在生产部署之前，始终在 Fork 模式下进行干跑：

```bash
# 启动 Fork 主网的本地节点
npx hardhat node --fork $MAINNET_RPC_URL

# 在 Fork 网络上执行部署脚本
npx hardhat run scripts/deploy_all.ts --network localhost

# 检查所有步骤是否正常
# 确认部署地址、事件、状态都符合预期
# 通过后再进行真实部署
```

### 8.5 紧急情况应对

| 情况 | 应对方案 |
|------|---------|
| 部署交易卡住（pending 超过 5 分钟） | 使用相同 nonce 发送一笔 0 ETH 给自己覆盖 |
| 部署到错误网络 | 检查 chainId（脚本自动检测 + 人工确认） |
| Gas 不足导致交易失败 | 增加 gas limit，重新部署（脚本支持重入） |
| 验证失败 | 检查 solc 版本、构造参数、网络是否正确 |

