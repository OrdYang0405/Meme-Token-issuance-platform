### 阶段 1：ERC20 接口规范复习（20min）

---

#### ① 强制接口回顾（8min）

**逐个讲解，板书对照：**

```
IERC20 核心接口（6 个函数 + 2 个事件）

┌─────────────────────────────────────────────────────────────┐
│  读操作（View Functions）                                     │
│  ├─ totalSupply() → uint256       // 代币总供应量              │
│  ├─ balanceOf(address) → uint256  // 某地址余额                │
│  └─ allowance(owner,spender) → uint256  // 授权额度             │
│                                                             │
│  写操作（State-Changing Functions）                           │
│  ├─ transfer(to, amount) → bool       // 直接转账              │
│  ├─ approve(spender, amount) → bool   // 授权                  │
│  └─ transferFrom(from, to, amount) → bool  // 代转账          │
│                                                             │
│  事件（Events）                                               │
│  ├─ Transfer(from indexed, to indexed, value)                │
│  └─ Approval(owner indexed, spender indexed, value)          │
└─────────────────────────────────────────────────────────────┘
```

**讲解要点：**

1. `totalSupply` — 链上唯一的代币总量记录，没有中心化数据库
2. `balanceOf` — 每个地址的"余额本"，本质是 `mapping(address => uint256)`
3. `approve` + `transferFrom` — ERC20 的核心创新
   - 生活类比：你授权支付宝从你银行卡扣款
   - DEX 交易必须 approve → transferFrom 两步走

---

#### ② approve + transferFrom 双步骤深入（8min）

**流程图讲解（黑板画出）：**

```
场景：用户想在 Uniswap 上卖出 100 TOKEN

步骤1：approve(UniswapRouter, 100)
  ┌──────────┐                    ┌───────────────┐
  │  用户 A   │ ──approve(路由,100)──→ │  allowance 映射  │
  │          │                    │ A→Router = 100 │
  └──────────┘                    └───────────────┘

步骤2：swapExactTokensForETH → Router 内部调用 transferFrom(A, 交易对, 100)
  ┌──────────┐   transferFrom     ┌──────────┐
  │  Router  │ ────────────────→  │   用户 A   │ balanceOf -= 100
  │          │                    │   交易对   │ balanceOf += 100
  └──────────┘                    └──────────┘
                    同时：allowance[A][Router] -= 100
```

**关键问题抛出：**
> "如果 allowance 设为 100，但只转了 30，剩余 70 还能用吗？"
> → 可以！只要 allowance >= 本次转账金额即可。

**安全风险预警：**
- `approve` 的竞态条件：先改 100 → 0，再改 0 → 50
- 解决方案：`increaseAllowance` / `decreaseAllowance`（OpenZeppelin 提供）

---

#### ③ decimals 精度机制（4min）

**讲解要点：**

```
链上存储的是整数，展示给人看的是小数

链上 totalSupply = 1000000000000000000000000（wei）
展示 totalSupply = 1,000,000.0（ether 单位）

换算关系：
  1 TOKEN = 10^decimals 个最小单位
  decimals = 18  → 1 ETH = 10^18 wei

为什么是 18？
  → 以太坊原生精度 18，兼容 ETH 结算习惯
  → 精度足够高，避免小数点误差
```

> **常见面试题：** USDC 的 decimals 是多少？
> → 6（因为美元最小单位是美分，1 USDC = 10^6 最小单位）

#### ② ERC20.sol 构造函数与内部变量（10min）

**逐段走读源码（教师投屏，逐行解释）：**

```solidity
abstract contract ERC20 is Context, IERC20, IERC20Metadata, IERC20Errors {
    // ⭐ 状态变量都是 private，子合约通过内部函数访问
    mapping(address => uint256) private _balances;         // 余额
    mapping(address => mapping(address => uint256)) private _allowances; // 授权
    uint256 private _totalSupply;                          // 总供应量
    string private _name;                                  // 名称
    string private _symbol;                                // 符号

    // ⭐ 构造函数：设置名称和符号
    constructor(string memory name_, string memory symbol_) {
        _name = name_;
        _symbol = symbol_;
    }

    // ⭐ 公开的 getter 函数
    function name() public view virtual returns (string memory) { return _name; }
    function symbol() public view virtual returns (string memory) { return _symbol; }
    function decimals() public view virtual returns (uint8) { return 18; }
    function totalSupply() public view virtual returns (uint256) { return _totalSupply; }
    function balanceOf(address account) public view virtual returns (uint256) {
        return _balances[account];
    }
```

**与上节课 HelloMeme 的对比：**
- OpenZeppelin 用 `private` + getter，而非 `public` 状态变量
- 好处：子合约可以覆盖 getter 逻辑（加税费等）

#### ③ transfer 与 _transfer 内部函数（10min）

```solidity
// ⭐ 外部接口
function transfer(address to, uint256 value) public virtual returns (bool) {
    address owner = _msgSender();
    _transfer(owner, to, value);
    return true;
}

// ⭐ 内部实现（子合约可以复用的核心逻辑）
function _transfer(address from, address to, uint256 value) internal {
    if (from == address(0)) {
        revert ERC20InvalidSender(address(0));    // 禁止从零地址转出
    }
    if (to == address(0)) {
        revert ERC20InvalidReceiver(address(0));  // 禁止转入零地址
    }
    _update(from, to, value);                     // ← 核心状态更新
}

// ⭐ _update：真正的状态变更函数（0.8.20 新增）
function _update(address from, address to, uint256 value) internal virtual {
    if (from == address(0)) {
        _totalSupply += value;      // 铸造
    } else {
        uint256 fromBalance = _balances[from];
        if (fromBalance < value) {
            revert ERC20InsufficientBalance(from, fromBalance, value);
        }
        unchecked { _balances[from] = fromBalance - value; }
    }
    if (to == address(0)) {
        unchecked { _totalSupply -= value; }  // 销毁
    } else {
        unchecked { _balances[to] += value; }
    }
    emit Transfer(from, to, value);
}
```

**重点讲解：**

| 原有设计（0.8.19 之前） | 新版设计（0.8.20+） |
|--------------------------|---------------------|
| `_transfer` 直接改状态 | `_transfer` → `_update` 集中处理 |
| `_mint` 独立实现 | `_mint` 也调用 `_update(address(0), to, value)` |
| `_beforeTokenTransfer` 钩子 | 被移除，改为覆盖 `_update` |

> **关键金句：** "`_update` 是所有代币流转的唯一通道——铸造（from=0）、销毁（to=0）、转账（两个都非0）都走这一个函数。"

#### ④ _mint 与 _burn 内部函数（5min）

```solidity
// ⭐ 铸造：from = address(0)
function _mint(address account, uint256 value) internal {
    if (account == address(0)) {
        revert ERC20InvalidReceiver(address(0));
    }
    _update(address(0), account, value);  // from=0 表示铸造
}

// ⭐ 销毁：to = address(0)
function _burn(address account, uint256 value) internal {
    if (account == address(0)) {
        revert ERC20InvalidSender(address(0));
    }
    _update(account, address(0), value);  // to=0 表示销毁
}
```

**设计哲学：**
- `_mint` / `_burn` / `_transfer` 都是 `internal`（内部函数）
- 子合约可以在自定义函数中调用它们
- 外部函数（`transfer`、`transferFrom`）通过 `_msgSender()` 获取调用者

#### ⑤ approve 与 transferFrom 源码（5min）

```solidity
function approve(address spender, uint256 value) public virtual returns (bool) {
    address owner = _msgSender();
    _approve(owner, spender, value);
    return true;
}

function _approve(address owner, address spender, uint256 value, bool) internal {
    if (owner == address(0)) revert ERC20InvalidApprover(address(0));
    if (spender == address(0)) revert ERC20InvalidSpender(address(0));
    _allowances[owner][spender] = value;
    emit Approval(owner, spender, value);
}

function transferFrom(address from, address to, uint256 value) public virtual returns (bool) {
    address spender = _msgSender();
    _spendAllowance(from, spender, value);    // 扣减授权额度
    _transfer(from, to, value);               // 执行转账
    return true;
}

function _spendAllowance(address owner, address spender, uint256 value) internal virtual {
    uint256 currentAllowance = allowance(owner, spender);
    if (currentAllowance != type(uint256).max) {   // ⭐ 无限授权不会扣减
        if (currentAllowance < value) {
            revert ERC20InsufficientAllowance(spender, currentAllowance, value);
        }
        _approve(owner, spender, currentAllowance - value, false);
    }
}
```

**关键知识点：无限授权（Infinite Approval）**

```solidity
// 如果 allowance == type(uint256).max，每次 transferFrom 不扣减
// 好处：节省 Gas（只需 approve 一次）
// 风险：合约有漏洞则所有余额可能被盗
```

#### ⑥ Context.sol 与 Ownable.sol 权限控制（5min）

**Context.sol：**
```solidity
abstract contract Context {
    function _msgSender() internal view virtual returns (address) {
        return msg.sender;
    }
    function _msgData() internal view virtual returns (bytes calldata) {
        return msg.data;
    }
}
```
- 为什么需要 `_msgSender()` 而不是直接 `msg.sender`？
- → 为 GSN（Gas Station Network）/ 元交易留扩展点

**Ownable.sol：**
```solidity
abstract contract Ownable is Context {
    address private _owner;

    constructor(address initialOwner) {
        _owner = initialOwner;
        emit OwnershipTransferred(address(0), initialOwner);
    }

    modifier onlyOwner() {
        _checkOwner();
        _;
    }

    function owner() public view virtual returns (address) { return _owner; }

    function transferOwnership(address newOwner) public virtual onlyOwner {
        _owner = newOwner;
        emit OwnershipTransferred(previousOwner, newOwner);
    }
}
```

> **教学提示：** 对比上节课自己手写的 `HelloMeme` 与 OpenZeppelin 成熟的工业级代码，强调"站在巨人肩膀上"的重要性。

#### ② StandardMemeToken 完整走读（15min）

**打开 `contracts/StandardMemeToken.sol`，逐段讲解：**

**1. 状态变量与事件**
```solidity
uint256 public maxSupply;     // 硬顶供应量（0 = 不限）
event Mint(address indexed to, uint256 amount);
event Burn(address indexed from, uint256 amount);
```

**2. 构造函数**
```solidity
constructor(
    string memory _name,
    string memory _symbol,
    uint256 _initialSupply,
    uint256 _maxSupply
) ERC20(_name, _symbol) Ownable(msg.sender) {
    maxSupply = _maxSupply;
    if (_initialSupply > 0) {
        _mint(msg.sender, _initialSupply * 10 ** decimals());
    }
}
```
- `_initialSupply = 0` 的场景：公平发射（Fair Launch），初始不铸造
- `_maxSupply = 0`：不限制最大供应量
- 为什么要乘以 `10 ** decimals()`？→ 精度转换

**3. mint 函数**
```solidity
function mint(address _to, uint256 _amount) public onlyOwner {
    uint256 amount = _amount * 10 ** decimals();
    if (maxSupply > 0) {
        require(totalSupply() + amount <= maxSupply * 10 ** decimals(), "exceeds max supply");
    }
    _mint(_to, amount);
    emit Mint(_to, amount);
}
```
- `onlyOwner` 修饰器 = 只有合约部署者能铸造
- maxSupply 硬顶保护
- 调用父合约的 `_mint` 内部函数

**4. burn 函数**
```solidity
function burn(uint256 _amount) public onlyOwner {
    uint256 amount = _amount * 10 ** decimals();
    _burn(msg.sender, amount);
    emit Burn(msg.sender, amount);
}
```
- 销毁的是 `msg.sender` 的余额（销毁者自己）
- 调用父合约的 `_burn` 内部函数

**5. 覆盖 decimals**
```solidity
function decimals() public pure override returns (uint8) {
    return 18;
}
```
- `override` 关键字：覆盖父合约同名函数
- 虽然默认就是 18，但显式声明可以防止误解

#### ① 测试框架讲解（5min）

**测试文件 `test/StandardMemeToken.test.ts` 结构：**

```typescript
describe("StandardMemeToken", function () {
  // ⭐ 每个测试用例前重新部署干净合约
  beforeEach(async function () {
    [owner, user] = await ethers.getSigners();
    const Factory = await ethers.getContractFactory("StandardMemeToken");
    token = await Factory.deploy("Standard Meme", "SMEME", 1_000_000, 10_000_000);
    await token.waitForDeployment();
  });

  // ⭐ 分组测试
  describe("Deployment", function () {
    it("should set correct name and symbol", async function () {
      expect(await token.name()).to.equal("Standard Meme");
      expect(await token.symbol()).to.equal("SMEME");
    });
  });
});
```

**Mocha + Chai 基础：**
- `describe` → 测试分组（可嵌套）
- `it` → 一个测试用例
- `beforeEach` → 每个 `it` 之前执行
- `expect(X).to.equal(Y)` → 断言
- `.to.be.revertedWith("...")` → 断言回滚
