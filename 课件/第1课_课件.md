### 阶段 1：Meme 代币市场认知（20min）

---

#### ① 开场引入（5min）

**讲解要点：**

1. 抛出问题："你知道哪些 Meme 代币？"
   - DOGE（2013）- 最早的 Meme 币，柴犬表情包，市值一度超过 800 亿美元
   - SHIB（2020）- "DOGE 杀手"，建立了完整的 ShibaSwap 生态
   - PEPE（2023）- 纯 Meme 无功能代币，发布仅 3 周市值突破 10 亿

2. Meme 现象背后的逻辑：
   - 社区驱动 > 技术驱动
   - FOMO 情绪放大器
   - 名人效应（Elon Musk 与 DOGE）
   - "代币化叙事" 的力量

---

#### ② Meme 代币核心机制拆解（10min）

**讲解要点（逐一在黑板上画出流程图）：**

```
一笔交易发生了什么？
用户 A ——100 Token——→ 用户 B
              │
              ├── 2% → 流动性池（LP）
              ├── 2% → 营销钱包
              ├── 1% → 直接燃烧
              └── 95% → 到达用户 B
```

1. **交易税费机制**
   - 买入税（Buy Tax） vs 卖出税（Sell Tax）
   - 为什么要分开设置？
   - 税费的分配方向：LP / 营销 / 燃烧

2. **自动流动性（SwapAndLiquify）**
   - 合约自动将累积的代币卖出 50% 换 ETH
   - 剩余 50% + 换取的 ETH → 添加流动性
   - 结果：价格底池不断增厚，持有者受益

3. **流动性锁仓**
   - 防止项目方跑路（Rug Pull）
   - 时间锁机制

4. **燃烧机制**
   - 每次交易销毁一部分，总供应量递减
   - 通缩属性吸引长期持有者

**关键金句：**
> "Meme 代币的核心不是技术创新，而是通过代币经济机制将社区共识转化为持久的市场支撑。"

#### ② 目录结构讲解（10min）

**讲解要点（逐层解释每个目录的作用）：**

```
meme-token-launchpad/
├── contracts/          ← 智能合约代码（Solidity）
├── test/               ← 测试文件（TypeScript + Chai）
├── scripts/            ← 部署与交互脚本
├── frontend/           ← 前端页面（后面课程创建）
├── hardhat.config.ts   ← Hardhat 核心配置
├── package.json        ← 依赖管理
├── tsconfig.json       ← TypeScript 配置
└── .env                ← 敏感信息（私钥、API Key）
```

**重点强调：**
- `contracts/` 里放 `.sol` 文件，一个合约一个文件
- `.env` 文件绝不提交到 Git，存敏感信息
- `hardhat.config.ts` 是所有配置的中枢

---

#### ③ TypeScript 配置讲解（5min）

**在 `tsconfig.json` 中解释：**

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "commonjs",
    "strict": true,
    "resolveJsonModule": true
  }
}
```

**关键点：**
- TypeScript 用于编写部署脚本和测试（合约本身是 Solidity）
- `strict: true` 开启严格类型检查，减少低级错误

### 阶段 3：Hardhat 配置详解（25min）

---

#### ① hardhat.config.ts 逐行解析（15min）

**打开 `hardhat.config.ts`，逐段讲解：**

**Part 1：导入与插件**
```typescript
import { HardhatUserConfig } from "hardhat/config";
import "@nomicfoundation/hardhat-toolbox";     // 工具箱（含 ethers, chai, verify 等）
import * as dotenv from "dotenv";              // 读取 .env 文件
dotenv.config();
```
- `hardhat-toolbox` 是一个"全家桶"，包含了开发常用插件
- `dotenv` 将 `.env` 加载到 `process.env`

**Part 2：编译器配置**
```typescript
solidity: {
  version: "0.8.20",
  settings: {
    optimizer: { enabled: true, runs: 200 },
  },
},
```
- `version`: Solidity 编译器版本
- `optimizer`: 优化器，`runs: 200` 表示中等优化（部署成本与运行成本的平衡）
  - `runs=1` → 最小部署成本
  - `runs=10000` → 最小运行成本

**Part 3：网络配置**
```typescript
networks: {
  hardhat: { chainId: 31337 },     // 本地内置网络
  sepolia: {
    url: process.env.SEPOLIA_RPC_URL || "",
    accounts: process.env.PRIVATE_KEY ? [process.env.PRIVATE_KEY] : [],
  },
},
```
- `hardhat` 网络：每次启动时自动创建，速度极快
- 本地网络不需要 RPC，也不需要真实 ETH
- `sepolia` 网络：真实的以太坊测试网
- RPC URL 从 `.env` 读取

**Part 4：Etherscan 验证**
```typescript
etherscan: {
  apiKey: process.env.ETHERSCAN_API_KEY,
},
```
- 部署后可以验证合约源码，让代码在浏览器上可见
- 本课不操作，后面课程会用到

**Part 5：路径配置**
```typescript
paths: {
  sources: "./contracts",
  tests: "./test",
  artifacts: "./artifacts",
},
```
- `artifacts`：编译产出的 ABI 和 bytecode
- 前端调用合约需要 ABI

### 阶段 4：第一个合约 — HelloMeme（25min）

---

#### ① 合约代码讲解（15min）

**打开 `contracts/HelloMeme.sol`，逐段讲解：**

**Part 1：许可声明与版本**
```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;
```
- `SPDX-License-Identifier`: 开源许可证标识（MIT 最宽松）
- `^0.8.20`: 编译器版本，`^` 表示兼容 0.8.20 及以上的 0.8.x

**Part 2：状态变量**
```solidity
string public name;              // 代币名称
string public symbol;            // 代币符号
uint8 public constant decimals = 18;   // 小数精度（固定 18）
uint256 public totalSupply;      // 总供应量
mapping(address => uint256) public balanceOf;               // 查询余额
mapping(address => mapping(address => uint256)) public allowance;  // 授权额度
```
- `public` 关键字：自动生成 getter 函数
- `mapping` 嵌套：`allowance[owner][spender] = amount`
- 为什么 `decimals = 18`？（以太坊原生精度惯例）

**Part 3：事件**
```solidity
event Transfer(address indexed from, address indexed to, uint256 value);
event Approval(address indexed owner, address indexed spender, uint256 value);
```
- `indexed`：允许按该字段过滤事件日志
- `Transfer(address(0), ..., ...)` = 铸造
- `Transfer(..., address(0), ...)` = 销毁

**Part 4：构造函数**
```solidity
constructor(string memory _name, string memory _symbol, uint256 _totalSupply) {
    name = _name;
    symbol = _symbol;
    totalSupply = _totalSupply * 10 ** decimals;
    balanceOf[msg.sender] = totalSupply;
    emit Transfer(address(0), msg.sender, totalSupply);
}
```
- `msg.sender`：谁部署合约，谁拿全部初始代币
- 总量乘以 `10**decimals`（如 totalSupply=100万 → 链上存储 1000000×10^18）
- 触发 `Transfer(address(0), ...)` 事件表示铸造

**Part 5：transfer**
```solidity
function transfer(address _to, uint256 _value) public returns (bool) {
    require(_to != address(0), "...");
    require(balanceOf[msg.sender] >= _value, "...");
    balanceOf[msg.sender] -= _value;
    balanceOf[_to] += _value;
    emit Transfer(msg.sender, _to, _value);
    return true;
}
```
- `require` 的三段式检查模式
- 先减后加的顺序（为什么？Checks-Effects-Interactions 模式简介）

**Part 6：approve 与 transferFrom**
- `approve`: 允许其他人花你的钱（授权）
- `transferFrom`: 代表别人转账（使用授权额度）
- allowance 使用后要扣减

**关键对比讲解：**
| 函数 | 谁调用 | 谁的钱被转 |
|------|--------|------------|
| transfer | 转账人自己 | msg.sender |
| transferFrom | 被授权者 | from 地址 |

#### ② 部署脚本讲解（5min）

**打开 `scripts/deploy.ts`：**

```typescript
const HelloMeme = await ethers.getContractFactory("HelloMeme");
const contract = await HelloMeme.deploy("Hello Meme", "HEME", 1_000_000);
await contract.waitForDeployment();
```

- `getContractFactory`: 在 `artifacts/` 中找编译后的合约
- `deploy`: 发送部署交易，传入构造函数参数
- `waitForDeployment`: 等待上链确认

**部署后验证：**
```typescript
const name = await contract.name();
const totalSupply = await contract.totalSupply();
console.log(ethers.formatEther(totalSupply));  // 1,000,000.0
```

#### ③ 学生实操（5min）

**学生操作清单：**

1. 确认 `contracts/HelloMeme.sol` 和 `scripts/deploy.ts` 已创建
2. 编译：

3. 部署到本地网络：

> - 编译失败：检查 Solidity 版本
