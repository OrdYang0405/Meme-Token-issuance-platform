## 二、知识回顾（5 分钟）

**Q1：MemeToken 的 `_update` 函数中包含了几层安全检查？分别是什么？**

> 答案：`contracts/MemeToken.sol:126-199` 包含 5 层检查：
> 1. 铸造/销毁短路（行127-130）：`from == address(0) || to == address(0)` → 跳过所有限制
> 2. 暂停检查（行133-135）：Pausable + 白名单例外
> 3. 交易开关检查（行138-140）：`tradingEnabled` + 白名单例外
> 4. 交易限额检查（行143-148）：`maxTransactionAmount` + `maxWalletAmount`
> 5. 税费扣取（行151-191）：买卖方向判断、税率计算、四路分配
>
> 测试需要覆盖每一层——边界条件、例外路径、权限校验。

**Q2：为什么 MemeToken 构造函数中需要手动设置 `isExcludedFromFee[msg.sender] = true`？**

> 答案：`contracts/MemeToken.sol:115-117` 在构造时就排除了 deployer 和合约自身。如果不排除，deployer 将代币转给其他人时会触发 `_update` 中的税费逻辑——但此时 `uniswapV2Pair` 还是 `address(0)`，`shouldTakeFee` 的判断条件 `from == uniswapV2Pair || to == uniswapV2Pair` 反而是 `false`，税费不会被扣，但这不是有意为之。排除的核心目的是让部署者在添加初始流动性时不触发交易限制。

**Q3：MemeFairLaunch 的 `_finalize` 函数在什么情况下被自动调用？**

> 答案：`contracts/MemeFairLaunch.sol:170-172`，在 `_processPurchase` 中当 `totalRaised >= hardCap` 时自动调用 `_finalize(true)`——即硬顶达到瞬间自动结束发射，不需要等待时间到期。这个行为必须在测试中验证。

**引入**：前三问都在问"这个逻辑对不对"——而回答"对不对"的唯一可靠手段就是自动化测试。本课将带你系统性地为 4 个合约建立超过 60 个测试用例，覆盖所有关键路径。

**关键配置解释**：

| 配置项 | 作用 | 注意事项 |
|--------|------|---------|
| `solidity.optimizer.enabled: true` | 编译时优化字节码 | 测试也必须开，否则 gas 估算不准 |
| `networks.hardhat.forking` | Mainnet Fork 模式 | 可访问主网所有合约状态 |
| `blockNumber: 19221000` | 固定分叉区块 | 确保测试可复现——状态不随主网新区块变化 |
| `chainId: 31337` | Hardhat 网络 ID | 与 `UNISWAP_ADDRESSES[31337]` 对应 |

> **课堂提问**：为什么要在 Hardhat 配置中固定 `blockNumber`，而不是每次都 Fork 最新区块？
>
> **答案**：可复现性。如果每次 Fork 最新区块，Uniswap Pair 中的储备量、WETH 价格都在变——今天通过的测试明天可能失败。固定区块号 = 固定链上状态 = 测试永远返回相同结果。测试的三大原则：**确定性、独立性、可复现性**。

## 四、单元测试实战：MemeToken（30 分钟）

### 4.1 测试文件总览与 AAA 模式

项目中 `test/MemeToken.test.ts`（335 行，8 个 `describe` 块，25+ 用例）与 `test/MemeToken.extended.test.ts`（新增，475 行，9 个 `describe` 块，30 用例）共同覆盖了 MemeToken 的全部关键路径。每个测试用例遵循 **AAA 模式**：

```
// Arrange（准备）→ Act（执行）→ Assert（断言）

it("should reject tax update within cooldown period", async function () {
    // Arrange：先执行一次更新，触发冷却期
    await token.setTax(200, 400);

    // Act + Assert：立即再次更新应被拒绝
    await expect(
        token.setTax(100, 200)
    ).to.be.revertedWith("tax cooldown active");
});
```

### 4.2 测试基础设施：beforeEach 与 Signer 管理

```typescript
// 文件：test/MemeToken.test.ts:1-31

import { expect } from "chai";
import { ethers } from "hardhat";
import { MemeToken } from "../typechain-types";
import { SignerWithAddress } from "@nomicfoundation/hardhat-ethers/signers";
import { time } from "@nomicfoundation/hardhat-network-helpers";

describe("MemeToken", function () {
  let token: MemeToken;
  let owner: SignerWithAddress;
  let marketing: SignerWithAddress;
  let team: SignerWithAddress;
  let buyer: SignerWithAddress;
  let seller: SignerWithAddress;
  let pair: SignerWithAddress;    // 模拟 Uniswap Pair

  const NAME = "Meme Token";
  const SYMBOL = "MEME";
  const TOTAL_SUPPLY = 1_000_000;
  const BUY_TAX = 300;           // 3% 买入税
  const SELL_TAX = 500;          // 5% 卖出税

  beforeEach(async function () {
    // ethers.getSigners() 返回 Hardhat 预置的 20 个测试账户
    [owner, marketing, team, buyer, seller, pair] = await ethers.getSigners();

    const Factory = await ethers.getContractFactory("MemeToken");
    token = await Factory.deploy(
      NAME, SYMBOL, TOTAL_SUPPLY,
      marketing.address, team.address, BUY_TAX, SELL_TAX
    );
    await token.waitForDeployment();

    // 设置 pair 地址——模拟 Uniswap Pair 存在
    await token.setUniswapPair(pair.address);
  });
```

**设计要点**：

| 设计决策 | 代码体现 | 原因 |
|---------|---------|------|
| `pair` 用 Signer 模拟 | `pair: SignerWithAddress` | 不需要部署真实的 Uniswap Pair 合约，用 EOA 地址模拟即可——`_update` 只检查 `from/to == uniswapV2Pair`，不调用 Pair 的任何函数 |
| 常量集中定义 | `const BUY_TAX = 300` | 全文件复用，避免魔法数字 |
| `beforeEach` 重新部署 | 每个 it 前都部署新合约 | 测试隔离——上一个用例的状态不影响下一个 |

### 4.4 所有权测试：Ownable2Step 两步转移

```typescript
// 文件：test/MemeToken.test.ts:47-83

describe("Ownership (Ownable2Step)", function () {
  it("should start two-step transfer", async function () {
    await token.transferOwnership(buyer.address);
    // 关键：pendingOwner 已设置，但 owner 不变
    expect(await token.pendingOwner()).to.equal(buyer.address);
    expect(await token.owner()).to.equal(owner.address);
  });

  it("should complete ownership transfer after accept", async function () {
    await token.transferOwnership(buyer.address);
    await token.connect(buyer).acceptOwnership();

    expect(await token.owner()).to.equal(buyer.address);
    expect(await token.pendingOwner()).to.equal(ethers.ZeroAddress);
  });

  it("should reject acceptOwnership from non-pending owner", async function () {
    await token.transferOwnership(buyer.address);
    await expect(
      token.connect(seller).acceptOwnership()
    ).to.be.revertedWithCustomError(token, "OwnableUnauthorizedAccount");
  });
});
```

**三种不同的断言风格，对应三种不同的失败模式**：

| 断言 API | 适用场景 | 示例 |
|----------|---------|------|
| `expect(x).to.equal(y)` | 状态值匹配 | `owner()` 返回预期地址 |
| `expect(tx).to.be.revertedWith("msg")` | require 回滚 + 错误消息 | `require(msg.sender == owner, "msg")` |
| `expect(tx).to.be.revertedWithCustomError(contract, "Error")` | 自定义错误回滚 | `OwnableUnauthorizedAccount(address)` |

> **关键技巧**：OpenZeppelin 5.x 使用 `custom error` 而非 `require` 字符串。`Ownable2Step` 在 `onlyOwner` 检查失败时抛出 `OwnableUnauthorizedAccount(account)`，必须用 `revertedWithCustomError` 匹配，不能用 `revertedWith`。

### 4.5 Pausable 测试：暂停与白名单例外

```typescript
// 文件：test/MemeToken.test.ts:86-123

describe("Pausable", function () {
  beforeEach(async function () {
    await token.enableTrading();  // 先开交易
  });

  it("should allow owner to pause and unpause", async function () {
    await token.pause();
    expect(await token.paused()).to.equal(true);
    await token.unpause();
    expect(await token.paused()).to.equal(false);
  });

  it("should reject transfers when paused", async function () {
    await token.transfer(buyer.address, ethers.parseEther("1000"));
    await token.pause();

    await expect(
      token.connect(buyer).transfer(seller.address, ethers.parseEther("100"))
    ).to.be.revertedWith("token transfers paused");
  });

  it("should allow whitelisted transfers when paused", async function () {
    await token.setWhitelist(buyer.address, true);
    await token.transfer(buyer.address, ethers.parseEther("1000"));
    await token.pause();

    // 白名单地址不受暂停影响
    await token.connect(buyer).transfer(seller.address, ethers.parseEther("100"));
    expect(await token.balanceOf(seller.address)).to.equal(ethers.parseEther("100"));
  });
});
```

**暂停测试的核心逻辑**：暂停 ≠ 绝对禁止。`contracts/MemeToken.sol:133-134` 的逻辑是：
```
paused() && !isWhitelisted[from] && !isWhitelisted[to] → revert
```
测试覆盖了三种情况：正常暂停禁止、暂停后恢复、暂停中白名单例外。**每一条 `require` 和 `if` 分支都需要一个测试用例**。

### 4.6 频率锁测试：time.increase 时间穿越

```typescript
// 文件：test/MemeToken.test.ts:126-171

describe("Update cooldown", function () {
  it("should allow first tax update", async function () {
    await token.setTax(200, 400);
    expect(await token.buyTax()).to.equal(200);
  });

  it("should reject tax update within cooldown period", async function () {
    await token.setTax(200, 400);
    await expect(
      token.setTax(100, 200)
    ).to.be.revertedWith("tax cooldown active");
  });

  it("should allow tax update after cooldown expires", async function () {
    await token.setTax(200, 400);

    // 核心：时间穿越 1 天 + 1 秒
    await time.increase(1 * 24 * 60 * 60 + 1);

    await token.setTax(100, 200);
    expect(await token.buyTax()).to.equal(100);
    expect(await token.sellTax()).to.equal(200);
  });

  it("should reject share update within cooldown period", async function () {
    await token.setTaxShares(2500, 2500, 2500, 2500);
    await expect(
      token.setTaxShares(3000, 3000, 2000, 2000)
    ).to.be.revertedWith("share cooldown active");
  });

  it("should allow share update after cooldown expires", async function () {
    await token.setTaxShares(2500, 2500, 2500, 2500);
    await time.increase(1 * 24 * 60 * 60 + 1);
    await token.setTaxShares(3000, 3000, 2000, 2000);
    expect(await token.liquidityShare()).to.equal(3000);
  });
});
```

**`time.increase` 的工作原理**：

```
Hardhat Network 在内存中维护一个 EVM 实例。
time.increase(seconds) 直接修改 EVM 的 block.timestamp，
不产生新区块——只是下一笔交易的 timestamp 被偏移了 seconds 秒。

正常流程：
  block 1 (t=100) → block 2 (t=112) → block 3 (t=124)
  └── 每个区块 timestamp 自然递增约 12 秒

time.increase(86400) 后：
  block 3 (t=124) → block 4 (t=86512) ← 下一笔交易的 timestamp
  └── 跳跃了 86400 秒，没有产生 7200 个中间区块
```

> **课堂提问**：为什么代码中写 `1 * 24 * 60 * 60 + 1` 而不是 `86401`？
>
> **答案**：**可读性优先**。`1 * 24 * 60 * 60 + 1` 一眼看出是"1 天 + 1 秒"，`86401` 需要心算。合约中 `TAX_COOLDOWN = 1 days`（Solidity），测试中对应 `1 * 24 * 60 * 60`（TypeScript）。+1 秒是确保超过 `>=` 的边界条件。

### 4.7 税费机制测试：从 Pair 买入 vs 卖出

```typescript
// 文件：test/MemeToken.test.ts:173-199

describe("Tax mechanism", function () {
  beforeEach(async function () {
    await token.enableTrading();
    // 安排流动性：seller 持有代币，pair 持有代币
    await token.transfer(seller.address, ethers.parseEther("10000"));
    await token.transfer(pair.address, ethers.parseEther("2000"));
  });

  it("should charge buy tax when buying from pair", async function () {
    const amount = ethers.parseEther("1000");
    const expectedTax = (amount * BigInt(BUY_TAX)) / 10000n;
    const expectedNet = amount - expectedTax;

    // pair → buyer = 买入方向
    await token.connect(pair).transfer(buyer.address, amount);
    expect(await token.balanceOf(buyer.address)).to.equal(expectedNet);
  });

  it("should charge sell tax and burn portion", async function () {
    const supplyBefore = await token.totalSupply();
    const amount = ethers.parseEther("1000");

    // seller → pair = 卖出方向
    await token.connect(seller).transfer(pair.address, amount);

    // 验证 burn 导致 totalSupply 减少
    expect(await token.totalSupply()).to.be.lt(supplyBefore);
  });
});
```

**税费测试的设计思路**：

```
买入路径：pair → buyer（from == uniswapV2Pair → 扣 buyTax）
卖出路径：seller → pair（to == uniswapV2Pair → 扣 sellTax）

                      ┌──────────────┐
                      │   MemeToken  │
                      └──────┬───────┘
                             │ _update
                    shouldTakeFee?
                    ┌────────┴────────┐
                    │ from == pair    │ to == pair
                    │ → buyTax 300    │ → sellTax 500
                    ▼                 ▼
              [buyer 收到 970]   [burn 部分销毁]
                                   totalSupply ↓
```


```typescript
// 文件：test/MemeFairLaunch.test.ts:6-39

import { MerkleTree } from "merkletreejs";
import keccak256 from "keccak256";

let merkleTree: MerkleTree;
let merkleRoot: string;

// 辅助函数：为指定地址生成 Merkle Proof
async function getMerkleProof(addr: string): Promise<string[]> {
  const leaf = keccak256(Buffer.from(addr.slice(2), "hex"));
  // 注意：去掉 0x 前缀再转 Buffer
  return merkleTree.getHexProof(leaf);
}

beforeEach(async function () {
  // ...部署 Token...

  // 构建 Merkle Tree：白名单 = buyer1-5
  const whitelist = [
    buyer1.address, buyer2.address, buyer3.address,
    buyer4.address, buyer5.address
  ];
  const leaves = whitelist.map(addr =>
    keccak256(Buffer.from(addr.slice(2), "hex"))
  );
  merkleTree = new MerkleTree(leaves, keccak256, { sortPairs: true });
  merkleRoot = "0x" + merkleTree.getRoot().toString("hex");

  // 部署 FairLaunch，传入 merkleRoot
  const LaunchFactory = await ethers.getContractFactory("MemeFairLaunch");
  launch = await LaunchFactory.deploy(
    await token.getAddress(),
    TOKENS_PER_ETH, TOKENS_FOR_SALE,
    SOFT_CAP, HARD_CAP, MAX_PER_WALLET,
    WHITELIST_DURATION, PUBLIC_DURATION,
    merkleRoot,
    ethers.ZeroAddress, LIQUIDITY_ETH, lpReceiver.address
  );
});
```

**MerkleTree 测试的三个关键细节**：

| 细节 | 代码 | 原因 |
|------|------|------|
| `sortPairs: true` | `new MerkleTree(leaves, keccak256, { sortPairs: true })` | 必须与 OZ 的 `MerkleProof.verify` 的排序方式一致 |
| `addr.slice(2)` | `Buffer.from(addr.slice(2), "hex")` | 去掉 `0x` 前缀——`keccak256` 期望纯 hex |
| `"0x" + merkleTree.getRoot()` | merkleRoot 构造 | `getRoot()` 返回 Buffer，转 hex 后需补 `0x` 前缀 |

```typescript
describe("Full fair launch flow", function () {
  it("whitelist → public → hard cap → claim tokens", async function () {
    // 成功路径：软顶达到 → 领取代币
    const proof = await getMerkleProof(buyer1.address);
    await launch.connect(buyer1).buyWhitelist(MAX_PER_WALLET, proof, {
      value: MAX_PER_WALLET,
    });

    await time.increase(WHITELIST_DURATION + 1);

    const amount1 = ethers.parseEther("15");
    const amount2 = HARD_CAP - MAX_PER_WALLET - amount1;
    await launch.connect(nonWhitelisted).buyPublic({ value: amount1 });
    await launch.connect(buyer2).buyPublic({ value: amount2 });

    expect(await launch.launchSucceeded()).to.equal(true);

    await launch.connect(buyer1).claimTokens();
    expect(await token.balanceOf(buyer1.address))
      .to.equal(MAX_PER_WALLET * TOKENS_PER_ETH);

    await launch.connect(nonWhitelisted).claimTokens();
    expect(await token.balanceOf(nonWhitelisted.address))
      .to.equal(amount1 * TOKENS_PER_ETH);
  });

  it("whitelist → time expires → below soft cap → refund", async function () {
    // 失败路径：未达软顶 → 退款
    const proof = await getMerkleProof(buyer1.address);
    const ethAmount = ethers.parseEther("3");
    await launch.connect(buyer1).buyWhitelist(ethAmount, proof, {
      value: ethAmount,
    });

    await time.increase(WHITELIST_DURATION + PUBLIC_DURATION + 1);
    await launch.finalize();

    expect(await launch.refundEnabled()).to.equal(true);

    const before = await ethers.provider.getBalance(buyer1.address);
    const tx = await launch.connect(buyer1).claimRefund();
    const receipt = await tx.wait();
    const after = await ethers.provider.getBalance(buyer1.address);
    expect(after - before + receipt!.fee).to.equal(ethAmount);
  });
});
```

**成功 vs 失败路径的状态对比**：

```
成功路径：totalRaised ≥ softCap
  finalize() → launchSucceeded = true
  → claimTokens() → 代币转到买家地址
  → withdrawUnsoldTokens() → owner 取回未售出代币
  → withdrawRaisedETH() → owner 取回募集的 ETH

失败路径：totalRaised < softCap
  finalize() → refundEnabled = true
  → claimRefund() → ETH 退回买家地址
  → 代币仍留在合约中（owner 可取回）
```

### 7.3 SwapAndLiquify 事件解析

```typescript
// 文件：test/MemeToken.uniswap.test.ts:126-156

it("should trigger SwapAndLiquify manually and emit event", async function () {
  const threshold = await token.swapThreshold();
  const accumulated = await token.accumulatedForLiquidity();

  if (accumulated >= threshold) {
    const tx = await token.triggerManualSwap();
    const receipt = await tx.wait();

    // 遍历 receipt 日志解析 SwapAndLiquify 事件
    let eventFound = false;
    for (const log of receipt.logs) {
      try {
        const parsed = token.interface.parseLog({
          topics: log.topics as string[],
          data: log.data,
        });
        if (parsed && parsed.name === "SwapAndLiquify") {
          eventFound = true;
          expect(parsed.args.tokensSwapped).to.be.greaterThan(0);
          expect(parsed.args.ethReceived).to.be.greaterThan(0);
        }
      } catch { continue; }
    }
    expect(eventFound).to.equal(true);

    // 验证累积量清零 → contracts/MemeToken.sol:212
    expect(await token.accumulatedForLiquidity()).to.equal(0);
  }
});
```

```typescript

  data: log.data,       // 非 indexed 参数（ABI 编码）
});
// parsed.name → "SwapAndLiquify"
// parsed.args.tokensSwapped → bigint
```
